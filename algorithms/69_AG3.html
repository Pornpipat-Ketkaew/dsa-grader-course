ZiplineZipline (ซิปไลน์)

Maximum spanning treeKruskal with union-find (longest first)Edge weights from geometry (3-D length)ต้นไม้ทอดข้ามที่มากที่สุดKruskal ด้วย union-find (ยาวที่สุดก่อน)น้ำหนักเส้นจากเรขาคณิต (ความยาวสามมิติ)O(M log M) time · O(N + M) memory★★☆

One connected network with no loop is a spanning tree, and the longest total wire is a maximum spanning tree. Each wire's length is √(D² + (Hᵢ − Hⱼ)²). Kruskal with the edges sorted longest first builds it.

เครือข่ายเดียวที่เชื่อมกันและไม่มีวงวนคือต้นไม้ทอดข้าม และลวดรวมยาวที่สุดคือต้นไม้ทอดข้ามที่มากที่สุด ความยาวลวดแต่ละเส้นคือ √(D² + (Hᵢ − Hⱼ)²) Kruskal ที่เรียงเส้นจากยาวไปสั้นสร้างมันได้

1Technique: maximum spanning tree with Kruskal

"Connect everything into one network" + "no way to come back to where you started" = a spanning tree (connected, no cycle, N − 1 edges). "Longest total" makes it a maximum spanning tree.

Kruskal builds it greedily: sort the edges from longest to shortest, and take each edge unless its two ends are already connected (that edge would close a cycle). A union-find answers "already connected?" in almost O(1). The proof is the MST cut property with every comparison reversed: the longest edge across any cut is safe to take.

2How it maps onto this problem

Step 1: the weight of each line

The wire hangs between two anchor points at different heights, so its length is the straight 3-D distance:

          Hᵢ ●
             |\
       ΔH    | \   wire = √(D² + ΔH²)
             |  \
             +---● Hⱼ
               D
sample 1: D = 60, ΔH = 45 − 20 = 25  →  √(3600 + 625) = 65.00

Compute it once, while reading, and store it with the edge.

Step 2: Kruskal, longest first

Sort the M lines by length decreasing, start with every tree in its own set, and take a line when findRoot(a) != findRoot(b). After N − 1 taken lines everything is one network (the input guarantees it is possible).

Step 3: output

fixed << setprecision(2), exactly as the statement suggests. Using double for the lengths is precise enough: the total is at most 99 lines of about 2 236 m.

Traps
  • Using D alone (ignoring the heights): sample 1 would print 60.00.
  • Sorting increasing (a minimum tree): sample 2 would be far too small.
  • Taking the M longest lines without the cycle check: the network may contain a loop.

3Solution

main.cpp⬇ .cpp
#include <iostream>
#include <iomanip>
#include <vector>
#include <cmath>
#include <algorithm>
using namespace std;

struct Zipline {
    double length;
    int a, b;
};

vector<int> parent;                          // union-find forest over the trees

int findRoot(int tree) {
    // walk up to the root, pointing every other node at its grandparent (path halving)
    while (parent[tree] != tree) {
        parent[tree] = parent[parent[tree]];
        tree = parent[tree];
    }
    return tree;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<int> height(n);
    // tree = 0..n-1: height of its anchor point
    for (int tree = 0; tree < n; tree++) cin >> height[tree];
    vector<Zipline> lines(m);
    // index = 0..m-1: a measured pair; the wire runs along the slope, so its
    // length is the hypotenuse of the ground distance and the height difference
    for (int index = 0; index < m; index++) {
        int ground;
        cin >> lines[index].a >> lines[index].b >> ground;
        int rise = height[lines[index].a] - height[lines[index].b];
        lines[index].length = sqrt((double)ground * ground + (double)rise * rise);
    }
    // Maximum spanning tree: Kruskal with the LONGEST lines first.
    sort(lines.begin(), lines.end(), [](const Zipline& x, const Zipline& y) { return x.length > y.length; });

    parent.resize(n);
    // tree = 0..n-1: every tree starts as its own network
    for (int tree = 0; tree < n; tree++) parent[tree] = tree;
    double wire = 0;
    // lines in decreasing length: take a line unless it would close a loop
    for (const Zipline& line : lines) {
        int rootA = findRoot(line.a), rootB = findRoot(line.b);
        if (rootA == rootB) continue;
        parent[rootA] = rootB;
        wire += line.length;
    }
    cout << fixed << setprecision(2) << wire << '\n';
}

1เทคนิค: ต้นไม้ทอดข้ามที่มากที่สุดด้วย Kruskal

"เชื่อมทุกอย่างเป็นเครือข่ายเดียว" + "ไม่มีทางวนกลับมาที่เดิม" = ต้นไม้ทอดข้าม (เชื่อมกัน ไม่มีวงรอบ มี N − 1 เส้น) "ยาวรวมมากที่สุด" ทำให้เป็นต้นไม้ทอดข้าม ที่มากที่สุด

Kruskal สร้างแบบโลภ: เรียงเส้นจากยาวไปสั้น แล้วเลือกทีละเส้น ยกเว้นปลายทั้งสองเชื่อมกันอยู่แล้ว (เส้นนั้นจะทำให้เกิดวงรอบ) union-find ตอบ "เชื่อมกันแล้วหรือยัง?" ได้เกือบ O(1) การพิสูจน์คือ cut property ของ MST ที่กลับทุกการเปรียบเทียบ: เส้นที่ยาวที่สุดที่ข้ามรอยแบ่งใด ๆ เลือกได้อย่างปลอดภัย

2นำมาใช้กับโจทย์นี้อย่างไร

ขั้นที่ 1: น้ำหนักของแต่ละเส้น

ลวดขึงระหว่างจุดเชื่อมสองจุดที่สูงต่างกัน ความยาวจึงเป็นระยะทางตรงสามมิติ:

          Hᵢ ●
             |\
       ΔH    | \   ลวด = √(D² + ΔH²)
             |  \
             +---● Hⱼ
               D
ตัวอย่าง 1: D = 60, ΔH = 45 − 20 = 25  →  √(3600 + 625) = 65.00

คำนวณครั้งเดียวตอนอ่าน แล้วเก็บไว้กับเส้น

ขั้นที่ 2: Kruskal เริ่มจากยาวที่สุด

เรียง M เส้นตามความยาว จากมากไปน้อย เริ่มให้ต้นไม้แต่ละต้นอยู่ในเซตของตัวเอง แล้วเลือกเส้นเมื่อ findRoot(a) != findRoot(b) หลังเลือกได้ N − 1 เส้น ทุกต้นอยู่ในเครือข่ายเดียวกัน (โจทย์รับประกันว่าทำได้)

ขั้นที่ 3: ผลลัพธ์

fixed << setprecision(2) ตามที่โจทย์แนะนำ double แม่นยำพอสำหรับความยาว: ผลรวมไม่เกิน 99 เส้น เส้นละราว 2 236 เมตร

กับดัก
  • ใช้แค่ D (ไม่สนความสูง): ตัวอย่าง 1 จะได้ 60.00
  • เรียงจากน้อยไปมาก (ต้นไม้ที่น้อยที่สุด): ตัวอย่าง 2 จะได้ค่าน้อยเกินไปมาก
  • เลือก M เส้นที่ยาวที่สุดโดยไม่ตรวจวงรอบ: เครือข่ายอาจมีวงวน
