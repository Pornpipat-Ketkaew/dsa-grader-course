Where you can go next depends on the room and on how many shots are left, so make that pair the vertex: (used, room). Each tunnel becomes two edges: walk it (same layer, its time) or shoot through it (next layer, time 0). Dijkstra on these (K + 1)·N states; the answer is the first exit state popped.

ที่ที่ไปต่อได้ขึ้นกับห้องและจำนวนกระสุนที่เหลือ จึงใช้คู่นั้นเป็นจุดยอด: (used, room) ทางเชื่อมแต่ละเส้นกลายเป็นสองเส้น: เดิน (ชั้นเดิม เสียเวลาของมัน) หรือยิงทะลุ (ชั้นถัดไป เวลา 0) รัน Dijkstra บน (K + 1)·N สถานะ คำตอบคือสถานะทางออกตัวแรกที่ถูก pop

1Technique: shortest path on a layered (state) graph

Dijkstra works on any graph with non-negative weights, not only on the map you are given. When the best move depends on more than the current position (here: how many free tunnels are left), put that extra information into the vertex:

vertex = (position, extra state). Edges describe how one step changes both.

With K ≤ 20 the extra state is small, so the new graph has (K + 1) copies of the map, called layers.

2How it maps onto this problem

Step 1: why the plain map is not enough

Sample 2 shows it. Reaching room 3 is fastest by shooting the first tunnel (time 0, no shots left), but then the 100-tunnel must be paid. Paying 1 to reach room 3 and keeping the shot for the 100-tunnel is better. So "the best time to reach room 3" has no single answer: it depends on the shots used. Keep one best time per (shots used, room).

Step 2: the edges

For each tunnel u – v with time t (both directions), from state (used, u):

  • walk: to (used, v), cost t;
  • shoot (if used < K): to (used + 1, v), cost 0.
layer used = 0:   1 ──1── 3 ──100── 2 ──5── 4
                         ╲ 0      ╲ 0
layer used = 1:   1 ──1── 3 ──100── 2 ──5── 4
best: (0,1)=0 → (0,3)=1 → shoot 3→2: (1,2)=1 → walk 2→4: (1,4)=6

All weights are ≥ 0 (zero is allowed), so Dijkstra is correct. An exit reached with fewer than K shots is fine: "at most K".

Step 3: Dijkstra with a heap

best[used][room], a min-heap of (time, used, room) with lazy deletion (skip an entry whose time is larger than the recorded best). The exit can be reached in any layer, but Dijkstra pops states in increasing time, so the first popped state with room = N is the answer; stop there.

Step 4: size and types

(K + 1)·N ≤ 2.1·10⁶ states and each tunnel gives up to 4 edges per layer: about 8·10⁶ relaxations, well within 2 s. Times reach 10⁵ · 10⁹: use long long.

Traps
  • Plain Dijkstra, then making the K slowest tunnels of that path free: sample 1 gives 7 instead of 4 (the statement warns about it).
  • One best time per room with "shots left" stored next to it: a faster arrival with fewer shots can wrongly block a slower arrival with more shots.
  • Answering best[K][N]: the exit may be reached with fewer shots and that layer can be smaller.
  • int times: overflow.

3Solution

main.cpp⬇ .cpp
#include <iostream>
#include <vector>
#include <queue>
#include <tuple>
#include <functional>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m, portals;
    cin >> n >> m >> portals;
    vector<vector<pair<int, int>>> tunnels(n + 1);   // tunnels[room] = (next room, time)
    // index = 0..m-1: every tunnel goes both ways
    for (int index = 0; index < m; index++) {
        int u, v, time;
        cin >> u >> v >> time;
        tunnels[u].push_back({v, time});
        tunnels[v].push_back({u, time});
    }

    // Layered graph: state (used, room) = "in this room, having fired the gun `used` times".
    // A tunnel from (used, room) goes to (used, next) for its time, or, if a shot
    // is left, to (used + 1, next) for 0. Dijkstra on these (K + 1) * N states.
    const long long UNREACHED = -1;
    vector<vector<long long>> best(portals + 1, vector<long long>(n + 1, UNREACHED));
    using State = tuple<long long, int, int>;        // (time so far, used, room)
    priority_queue<State, vector<State>, greater<State>> heap;
    best[0][1] = 0;
    heap.push({0, 0, 1});
    long long answer = UNREACHED;
    // pop states in increasing time
    while (!heap.empty()) {
        auto [timeHere, used, room] = heap.top();
        heap.pop();
        if (timeHere > best[used][room]) continue;     // outdated entry
        if (room == n) {                               // the first popped exit state is the best one
            answer = timeHere;
            break;
        }
        auto relax = [&](int nextUsed, int next, long long arrive) {
            if (best[nextUsed][next] == UNREACHED || arrive < best[nextUsed][next]) {
                best[nextUsed][next] = arrive;
                heap.push({arrive, nextUsed, next});
            }
        };
        for (auto [next, time] : tunnels[room]) {
            relax(used, next, timeHere + time);                  // walk the tunnel
            if (used < portals) relax(used + 1, next, timeHere); // shoot a portal through it
        }
    }
    cout << answer << '\n';
}

1เทคนิค: เส้นทางสั้นที่สุดบนกราฟหลายชั้น (กราฟสถานะ)

Dijkstra ใช้ได้กับกราฟ ใดก็ได้ ที่น้ำหนักไม่ติดลบ ไม่ใช่แค่แผนที่ที่โจทย์ให้มา เมื่อการเดินที่ดีที่สุดขึ้นกับมากกว่าตำแหน่งปัจจุบัน (ในข้อนี้: เหลือทางเชื่อมฟรีอีกกี่ครั้ง) ให้ใส่ข้อมูลเพิ่มนั้นเข้าไปในจุดยอด:

จุดยอด = (ตำแหน่ง, สถานะเพิ่ม) เส้นอธิบายว่าการเดินหนึ่งก้าวเปลี่ยนทั้งสองอย่างอย่างไร

เมื่อ K ≤ 20 สถานะเพิ่มมีขนาดเล็ก กราฟใหม่จึงเป็นสำเนาของแผนที่ (K + 1) ชุด เรียกว่า ชั้น (layer)

2นำมาใช้กับโจทย์นี้อย่างไร

ขั้นที่ 1: ทำไมแผนที่ธรรมดาไม่พอ

ตัวอย่าง 2 แสดงให้เห็น การไปห้อง 3 เร็วที่สุดคือยิงทางเชื่อมแรก (เวลา 0 ไม่เหลือกระสุน) แต่แล้วต้องจ่ายทางเชื่อม 100 การจ่าย 1 เพื่อไปห้อง 3 แล้วเก็บกระสุนไว้ใช้กับทางเชื่อม 100 ดีกว่า "เวลาที่ดีที่สุดในการไปห้อง 3" จึงไม่มีคำตอบเดียว: ขึ้นกับจำนวนกระสุนที่ใช้ไป เก็บเวลาที่ดีที่สุด ต่อ (จำนวนที่ใช้ไป, ห้อง)

ขั้นที่ 2: เส้นของกราฟ

สำหรับทางเชื่อม u – v ที่ใช้เวลา t (ทั้งสองทิศ) จากสถานะ (used, u):

  • เดิน: ไป (used, v) เสีย t
  • ยิง (ถ้า used < K): ไป (used + 1, v) เสีย 0
ชั้น used = 0:   1 ──1── 3 ──100── 2 ──5── 4
                        ╲ 0      ╲ 0
ชั้น used = 1:   1 ──1── 3 ──100── 2 ──5── 4
ดีที่สุด: (0,1)=0 → (0,3)=1 → ยิง 3→2: (1,2)=1 → เดิน 2→4: (1,4)=6

น้ำหนักทั้งหมด ≥ 0 (เป็น 0 ได้) Dijkstra จึงถูกต้อง การถึงทางออกด้วยกระสุนน้อยกว่า K ก็ได้: "ไม่เกิน K"

ขั้นที่ 3: Dijkstra ด้วย heap

best[used][room] และ min-heap ของ (เวลา, used, ห้อง) แบบลบช้า (ข้ามรายการที่เวลามากกว่าค่าที่บันทึกไว้) ทางออกไปถึงได้ในชั้นใดก็ได้ แต่ Dijkstra pop สถานะตามเวลาจากน้อยไปมาก สถานะแรกที่ pop ได้ห้อง = N จึงเป็นคำตอบ หยุดได้ทันที

ขั้นที่ 4: ขนาดและชนิดข้อมูล

(K + 1)·N ≤ 2.1·10⁶ สถานะ และทางเชื่อมแต่ละเส้นให้ได้ถึง 4 เส้นต่อชั้น: ราว 8·10⁶ ครั้งของการปรับค่า สบาย ๆ ใน 2 วินาที เวลาสูงถึง 10⁵ · 10⁹: ใช้ long long

กับดัก
  • Dijkstra ธรรมดา แล้วให้ K ทางที่นานที่สุดของ เส้นทางนั้น ฟรี: ตัวอย่าง 1 ได้ 7 แทน 4 (โจทย์เตือนไว้)
  • เก็บเวลาดีที่สุดหนึ่งค่าต่อห้องพร้อม "กระสุนที่เหลือ": การมาถึงที่เร็วกว่าแต่กระสุนน้อยกว่าอาจบังการมาถึงที่ช้ากว่าแต่กระสุนมากกว่าอย่างผิด ๆ
  • ตอบ best[K][N]: ทางออกอาจถึงได้ด้วยกระสุนน้อยกว่าและชั้นนั้นอาจน้อยกว่า
  • เวลาเป็น int: ล้น

#include <vector>
#include <queue>
#include <tuple>
#include <functional>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m, portals;
    cin >> n >> m >> portals;

        auto [timeHere, used, room] = heap.top();
        heap.pop();
        if (timeHere > best[used][room]) continue;     // outdated entry
        if (room == n) {                               // the first popped exit state is the best one
            answer = timeHere;
            break;
        }
        auto relax = [&](int nextUsed, int next, long long arrive) {
            if (best[nextUsed][next] == UNREACHED || arrive < best[nextUsed][next]) {

                heap.push({arrive, nextUsed, next});

Tested. all 4 PDF samples, N = 1, a single 10⁹ tunnel with K = 0, 300 random maps against a brute force that tries every simple path and makes its K slowest tunnels free, and N = M = 100 000 with K = 20 (2.1 million states) in 0.17 s and 0.30 s.ทดสอบแล้ว ตัวอย่างทั้ง 4 ใน PDF, N = 1, ทางเชื่อมเดียวที่ใช้เวลา 10⁹ กับ K = 0, แผนที่สุ่ม 300 ชุดเทียบกับ brute force ที่ลองทุกเส้นทางที่ไม่ซ้ำห้องแล้วให้ K ทางที่นานที่สุดเป็น 0 และ N = M = 100 000 กับ K = 20 (2.1 ล้านสถานะ) ใช้ 0.17 และ 0.30 วินาที
