ex07e2_iss

Increasing Sequence SumIncreasing Sequence Sum (นับการแบ่งจำนวน)

Counting DP (unorderedcoin-change order)Allow one part size at a timeDP นับวิธี (ไม่สนลำดับ แบบ coin change)อนุญาตขนาดชิ้นทีละขนาดO(N²) time · O(N) memory★★☆

A non-decreasing sequence is a partition of N written in sorted order, so order must NOT create new answers. Allow part sizes 1, 2, …, N one at a time in the outer loop and update ways[sum] += ways[sum − part] for increasing sums: every sequence is then built only in its sorted order.

ลำดับที่ไม่ลดคือการแบ่งจำนวน N ที่เขียนเรียงแล้ว ลำดับจึง **ต้องไม่** สร้างคำตอบใหม่ อนุญาตขนาดชิ้น 1, 2, …, N ทีละขนาดในลูปนอก และอัปเดต ways[sum] += ways[sum − part] สำหรับ sum ที่เพิ่มขึ้น แล้วทุกลำดับจะถูกสร้างแค่ในลำดับที่เรียงแล้วเท่านั้น

1Technique: counting without order (the coin-change loop order)

Compare with Chocolate: there [1,3] and [3,1] were different, so we split by the last piece and every order was counted. Here <1, 2, 2> is allowed but <2, 1, 2> is not, so each multiset of parts must be counted once.

The standard trick is to fix the order in which parts may appear: build sequences that use parts 1..part only, adding one new part size per outer step.

ways[0] = 1
for part = 1..N:               // allow one more size
    for sum = part..N:         // increasing: `part` can repeat
        ways[sum] += ways[sum - part]

After the outer step for part, ways[sum] = number of non-decreasing sequences with this sum whose parts are all ≤ part.

2How it maps onto this problem

Step 1: why each sequence is counted exactly once

A non-decreasing sequence ending in part is "a non-decreasing sequence with sum sum − part and parts ≤ part, followed by part". Those already include sequences ending in part (because the inner loop runs upward, ways[sum − part] was updated earlier in the same outer step), so any number of copies of part is allowed. Sequences whose largest part is smaller were counted in earlier outer steps. Each sequence is generated by appending its parts in sorted order, which is unique.

Step 2: the loop order is the whole point

Swapping the loops (sum outside, part inside) gives the Chocolate recurrence and counts ordered sequences: for N = 5 it would print 16 instead of 7.

Step 3: size

p(100) = 190 569 292 fits in int; long long is used anyway.

3Solution

main.cpp⬇ .cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    // ways[sum] = number of non-decreasing sequences with this sum using only parts 1..part
    vector<long long> ways(n + 1, 0);
    ways[0] = 1;                                     // the empty sequence
    // part = 1..n: allow one more part size, smallest first, so each sequence is
    // built in sorted order and counted exactly once
    for (int part = 1; part <= n; part++) {
        // sum = part..n (increasing): ways[sum - part] may already use `part`,
        // which lets a part repeat any number of times
        for (int sum = part; sum <= n; sum++) ways[sum] += ways[sum - part];
    }
    cout << ways[n] << '\n';
}

1เทคนิค: นับแบบไม่สนลำดับ (ลำดับลูปแบบ coin change)

เทียบกับ Chocolate: ที่นั่น [1,3] กับ [3,1] ต่างกัน เราจึงแบ่งตามชิ้น สุดท้าย และนับทุกลำดับ ข้อนี้ <1, 2, 2> ใช้ได้แต่ <2, 1, 2> ใช้ไม่ได้ ชุดของชิ้นแต่ละชุดจึงต้องนับ ครั้งเดียว

เทคนิคมาตรฐานคือกำหนดลำดับที่ชิ้นแต่ละขนาดจะปรากฏ: สร้างลำดับที่ใช้ชิ้น 1..part เท่านั้น โดยเพิ่มขนาดชิ้นใหม่หนึ่งขนาดต่อหนึ่งรอบของลูปนอก

ways[0] = 1
for part = 1..N:               // อนุญาตขนาดเพิ่มอีกหนึ่ง
    for sum = part..N:         // เพิ่มขึ้น: `part` ซ้ำได้
        ways[sum] += ways[sum - part]

หลังลูปนอกรอบของ part แล้ว ways[sum] = จำนวนลำดับไม่ลดที่มีผลรวมนี้และทุกชิ้น ≤ part

2นำมาใช้กับโจทย์นี้อย่างไร

ขั้นที่ 1: ทำไมแต่ละลำดับถูกนับครั้งเดียวพอดี

ลำดับไม่ลดที่จบด้วย part คือ "ลำดับไม่ลดที่ผลรวม sum − part และทุกชิ้น ≤ part ตามด้วย part" ซึ่งรวมลำดับที่จบด้วย part อยู่แล้ว (เพราะลูปในวิ่งขึ้น ways[sum − part] ถูกอัปเดตไปก่อนในรอบนอกเดียวกัน) จึงใช้ part กี่ชิ้นก็ได้ ส่วนลำดับที่ชิ้นใหญ่สุดเล็กกว่านั้นถูกนับในรอบนอกก่อนหน้า ทุกลำดับถูกสร้างโดยต่อชิ้นตามลำดับที่เรียงแล้ว ซึ่งมีแบบเดียว

ขั้นที่ 2: ลำดับของลูปคือหัวใจ

ถ้าสลับลูป (sum อยู่นอก part อยู่ใน) จะได้สูตรของ Chocolate และนับลำดับที่ลำดับสำคัญ: N = 5 จะพิมพ์ 16 แทน 7

ขั้นที่ 3: ขนาดตัวเลข

p(100) = 190 569 292 ใส่ int ได้ แต่ใช้ long long ไว้
