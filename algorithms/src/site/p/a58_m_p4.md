## Technique: pick the greedy rule, then try to break it

The problem PDF in this folder is identical to [Class Selection](ex04e1_interval.html); read that page for the algorithm and the exchange-argument proof. This page trains the step that comes **before** a proof in an exam: when several greedy orders look plausible, test each one on tiny inputs and throw away every rule that loses even once.

## How it maps onto this problem

### Step 1: four candidate rules

Every candidate has the same shape: sort the classes by some key, then keep each class that overlaps nothing kept so far. Only the key changes.

| rule (key) | idea behind it |
|---|---|
| earliest **finish** | free the room as early as possible |
| earliest **start** | start using the room as early as possible |
| **shortest** duration | short classes block less time |
| **fewest overlaps** | classes that clash with few others are "cheap" |

### Step 2: break the wrong ones

```diagram
earliest start:   [0..........10]          picks the long class first  → 1
                    [1-2] [3-4] [5-6]       optimal                     → 3

shortest:         [0-----5]   [5-----10]    optimal                     → 2
                        [4-6]               shortest is taken first     → 1

fewest overlaps:  [0-2][2-4][4-6][6-8]      optimal (top row)           → 4
                    [1-3]x3 [3-5] [5-7]x3   [3-5] has the fewest clashes,
                                            taking it blocks two tops   → 3
```

Run all four rules on each preset below and watch which one survives.

### Step 3: the survivor

Only **earliest finish** wins on every input, and the exchange argument on the [Class Selection](ex04e1_interval.html) page proves it always will. The solution below is that greedy.

:::key Exam habit
Before coding a greedy, spend two minutes on 3- or 4-interval counterexamples for each candidate rule. A rule that survives is not yet proven, but a rule that fails is certainly wrong.
:::

## นำมาใช้กับโจทย์นี้อย่างไร

### ขั้นที่ 1: กฎที่เป็นตัวเลือกสี่แบบ

ทุกตัวเลือกมีรูปแบบเดียวกัน: เรียงวิชาตาม key บางอย่าง แล้วเก็บทุกวิชาที่ไม่ทับกับวิชาที่เก็บไว้แล้ว ต่างกันแค่ key

| กฎ (key) | แนวคิด |
|---|---|
| **จบ** เร็วที่สุด | ปล่อยห้องให้ว่างเร็วที่สุด |
| **เริ่ม** เร็วที่สุด | เริ่มใช้ห้องให้เร็วที่สุด |
| **สั้น** ที่สุด | วิชาสั้นกินเวลาน้อย |
| **ทับน้อย** ที่สุด | วิชาที่ชนกับวิชาอื่นน้อย "ราคาถูก" |

### ขั้นที่ 2: ทำให้กฎที่ผิดพัง

```diagram
เริ่มเร็วสุด:      [0..........10]          เลือกวิชายาวก่อน             → 1
                    [1-2] [3-4] [5-6]       ดีที่สุด                     → 3

สั้นที่สุด:        [0-----5]   [5-----10]    ดีที่สุด                     → 2
                        [4-6]               วิชาสั้นสุดถูกเลือกก่อน       → 1

ทับน้อยที่สุด:     [0-2][2-4][4-6][6-8]      ดีที่สุด (แถวบน)              → 4
                    [1-3]x3 [3-5] [5-7]x3   [3-5] ชนน้อยที่สุด
                                            เลือกมันแล้วบังแถวบนสองวิชา  → 3
```

ลองรันทั้งสี่กฎบนแต่ละ preset ด้านล่าง แล้วดูว่ากฎไหนรอด
