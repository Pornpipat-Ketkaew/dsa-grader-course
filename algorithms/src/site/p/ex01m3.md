## Technique: binary search on the answer

Sometimes computing the answer directly is hard, but **checking a guess** is easy, and the check is monotone: if guess t works, every larger t works too. Then binary search over the **answer values** instead of over an array:

```cpp
// low fails, high works
while (high - low > 1) {
    middle = low + (high - low) / 2;
    if (works(middle)) high = middle; else low = middle;
}
// high = smallest value that works
```

The cost is (cost of one check) × log₂(range of answers). Ranges like 10¹⁵ need only 50 steps.

## How it maps onto this problem

### Step 1: the check

"Customer c is seated by time t" ⇔ "at least c customers are seated by time t". Chef i, starting at time 0 and taking exactly Tᵢ per customer, seats someone at 0, Tᵢ, 2Tᵢ, …: that is ⌊t / Tᵢ⌋ + 1 customers by time t. So

> seatedBy(t) = Σᵢ (⌊t / Tᵢ⌋ + 1),   and c is seated at the smallest t with seatedBy(t) ≥ c.

seatedBy grows with t, which is all binary search needs. Which seat customer c takes does not matter, only when.

```diagram
T = 2 2 5        t:          0  1  2  3  4
seatedBy(t):                 3  3  5  5  7
customer 4 → first t with ≥ 4 is 2;   customer 6 → first t with ≥ 6 is 4
```

### Step 2: the bounds

- low = −1: before opening nobody is seated (always fails).
- high = (c − 1)·min T: the fastest chef alone has seated c people by then (always works).

With c ≤ 10¹² and T ≤ 1 000, high ≤ 10¹⁵ and seatedBy ≤ 1 000 · 10¹⁵ = 10¹⁸, still inside `long long`.

{{viz}}

### Step 3: cost

200 queries × 50 steps × 1 000 chefs = 10⁷ divisions.

:::warn Traps
- Simulating with a heap: correct (it is the brute force in the tests) but 10¹² steps.
- Forgetting the "+ 1" (everyone seated at time 0): the first N customers would come out wrong.
- `int` for t or the count: both exceed 2³¹ immediately.
:::

## เทคนิค: binary search บนคำตอบ

บางครั้งการคำนวณคำตอบตรง ๆ ยาก แต่ **การตรวจค่าที่เดา** ง่าย และการตรวจเป็นทางเดียว: ถ้าค่า t ใช้ได้ ทุก t ที่มากกว่าก็ใช้ได้ด้วย จึง binary search บน **ค่าของคำตอบ** แทนบนอาร์เรย์:

```cpp
// low ใช้ไม่ได้, high ใช้ได้
while (high - low > 1) {
    middle = low + (high - low) / 2;
    if (works(middle)) high = middle; else low = middle;
}
// high = ค่าที่น้อยที่สุดที่ใช้ได้
```

ต้นทุนคือ (ต้นทุนการตรวจหนึ่งครั้ง) × log₂(ช่วงของคำตอบ) ช่วงขนาด 10¹⁵ ใช้แค่ 50 ขั้น

## นำมาใช้กับโจทย์นี้อย่างไร

### ขั้นที่ 1: การตรวจ

"ลูกค้า c ได้นั่งภายในเวลา t" ⇔ "มีลูกค้าได้นั่งอย่างน้อย c คนภายในเวลา t" เชฟ i เริ่มที่เวลา 0 และใช้เวลา Tᵢ ต่อคนพอดี จึงให้คนนั่งที่ 0, Tᵢ, 2Tᵢ, …: เท่ากับ ⌊t / Tᵢ⌋ + 1 คนภายในเวลา t ดังนั้น

> seatedBy(t) = Σᵢ (⌊t / Tᵢ⌋ + 1) และลูกค้า c ได้นั่งที่ t ที่น้อยที่สุดที่ seatedBy(t) ≥ c

seatedBy เพิ่มตาม t ซึ่งคือทั้งหมดที่ binary search ต้องการ ลูกค้า c ได้ที่นั่งไหนไม่สำคัญ สำคัญแค่เมื่อไหร่

```diagram
T = 2 2 5        t:          0  1  2  3  4
seatedBy(t):                 3  3  5  5  7
ลูกค้า 4 → t แรกที่ ≥ 4 คือ 2;   ลูกค้า 6 → t แรกที่ ≥ 6 คือ 4
```

### ขั้นที่ 2: ขอบเขต

- low = −1: ก่อนเปิดร้านยังไม่มีใครนั่ง (ใช้ไม่ได้เสมอ)
- high = (c − 1)·min T: เชฟที่เร็วที่สุดคนเดียวก็รับครบ c คนในเวลานั้น (ใช้ได้เสมอ)

เมื่อ c ≤ 10¹² และ T ≤ 1 000 จะได้ high ≤ 10¹⁵ และ seatedBy ≤ 1 000 · 10¹⁵ = 10¹⁸ ยังอยู่ใน `long long`

{{viz}}

### ขั้นที่ 3: ต้นทุน

200 คำถาม × 50 ขั้น × เชฟ 1 000 คน = การหาร 10⁷ ครั้ง

:::warn กับดัก
- จำลองด้วย heap: ถูก (เป็น brute force ในการทดสอบ) แต่ 10¹² ขั้น
- ลืม "+ 1" (ทุกคนได้นั่งที่เวลา 0): ลูกค้า N คนแรกจะผิด
- t หรือจำนวนเป็น `int`: เกิน 2³¹ ทันที
:::
