## Technique: a counting array indexed by value

When the values you care about are **small integers** (here 1..n with n ≤ 100 000), the fastest possible "have I seen x?" structure is a plain array `seen[x]`. Reading and writing it costs O(1), with no hashing and no sorting.

The second tool is a counting fact, the **pigeonhole principle**: if you put n values into n boxes and no box gets two, then every box gets exactly one.

## How it maps onto this problem

:::key The reduction
"f is a permutation of A = {1..n}" sounds like three checks (1-1, onto, B = A). Pigeonhole turns it into **two**, and both are local to one value:

1. **range**: every dᵢ is inside 1..n;
2. **no repeat**: no value appears twice.

If both hold, n distinct values all live in n boxes 1..n, so every box is hit: f is onto for free.
:::

So the program is one left-to-right pass with a `seen[]` array:

```diagram
read value ─┬─ value < 1 or value > n ? ──► NO   (f(i) is outside A)
            ├─ seen[value] already true ? ──► NO   (two i share a value: not 1-1)
            └─ otherwise: seen[value] = true, continue
end of input without a NO  ──► YES
```

Order matters: test the **range before** touching `seen[value]`. A value like −2 or 2·10⁹ would index outside the array.

Watch the three samples run. Green cells are boxes already filled; the amber cell is the box the current value wants.

{{viz}}

:::warn Shortcuts that are wrong
- **Only checking repeats.** With n = 3, `1 2 7` has no repeat but 7 is outside 1..3: the answer is NO.
- **Comparing the sum with n(n+1)/2.** `1 1 4` and `1 2 3` both sum to 6.
- **`int` for the values.** ±2·10⁹ fits in `int` (limit ≈ 2.147·10⁹), but only just; `long long` costs nothing here.
:::

Sorting the values and checking `sorted[i] == i + 1` also works, but it is O(n log n) and needs the whole array. The counting array is O(n) and can stop at the first bad value.

## เทคนิค: อาร์เรย์นับที่ใช้ค่าเป็นดัชนี

เมื่อค่าที่เราสนใจเป็น **จำนวนเต็มเล็ก ๆ** (ในข้อนี้คือ 1..n โดย n ≤ 100 000) โครงสร้างที่เร็วที่สุดสำหรับคำถาม "เคยเห็น x หรือยัง?" คืออาร์เรย์ธรรมดา `seen[x]` อ่าน/เขียนได้ใน O(1) ไม่ต้องแฮช ไม่ต้องเรียง

เครื่องมือที่สองคือข้อเท็จจริงเชิงการนับ **หลักรังนกพิราบ (pigeonhole principle)**: ถ้าใส่ของ n ชิ้นลงกล่อง n ใบ และไม่มีกล่องไหนได้สองชิ้น ทุกกล่องจะได้พอดีหนึ่งชิ้น

## นำมาใช้กับโจทย์นี้อย่างไร

:::key การลดรูปปัญหา
"f เป็น permutation ของ A = {1..n}" ฟังดูเหมือนต้องตรวจสามอย่าง (หนึ่งต่อหนึ่ง, ทั่วถึง, B = A) หลักรังนกพิราบทำให้เหลือแค่ **สองอย่าง** และทั้งสองตรวจได้ทีละค่า:

1. **ช่วงค่า**: dᵢ ทุกตัวอยู่ใน 1..n
2. **ไม่ซ้ำ**: ไม่มีค่าใดปรากฏสองครั้ง

ถ้าผ่านทั้งสองข้อ ค่าที่ต่างกัน n ค่าอยู่ในกล่อง 1..n ทั้ง n ใบ ทุกกล่องจึงถูกใช้ แปลว่า f ทั่วถึงโดยอัตโนมัติ
:::

โปรแกรมจึงเป็นการเดินจากซ้ายไปขวารอบเดียวพร้อมอาร์เรย์ `seen[]`:

```diagram
อ่าน value ─┬─ value < 1 หรือ value > n ? ──► NO   (f(i) อยู่นอก A)
            ├─ seen[value] เป็น true แล้ว ? ──► NO   (มี i สองตัวให้ค่าเดียวกัน: ไม่ใช่ 1-1)
            └─ นอกนั้น: seen[value] = true แล้วไปต่อ
อ่านครบโดยไม่เจอ NO  ──► YES
```

ลำดับการตรวจสำคัญ: ตรวจ **ช่วงค่าก่อน** แตะ `seen[value]` เสมอ เพราะค่าอย่าง −2 หรือ 2·10⁹ จะชี้ออกนอกอาร์เรย์

ลองดูทั้งสามตัวอย่างทำงานทีละขั้น ช่องสีเขียวคือกล่องที่ถูกใช้แล้ว ช่องสีส้มคือกล่องที่ค่าปัจจุบันต้องการ

{{viz}}

:::warn ทางลัดที่ผิด
- **ตรวจแค่ค่าซ้ำ** เช่น n = 3 กับ `1 2 7` ไม่มีค่าซ้ำ แต่ 7 อยู่นอก 1..3 คำตอบคือ NO
- **เทียบผลรวมกับ n(n+1)/2** เพราะ `1 1 4` กับ `1 2 3` รวมได้ 6 เท่ากัน
- **ใช้ `int` เก็บค่า** ±2·10⁹ ยังพอดีกับ `int` (ขีดจำกัด ≈ 2.147·10⁹) แต่เฉียดมาก ใช้ `long long` ไม่เสียอะไรเลย
:::

การเรียงค่าแล้วตรวจ `sorted[i] == i + 1` ก็ได้คำตอบถูก แต่ใช้ O(n log n) และต้องเก็บทั้งอาร์เรย์ ส่วนอาร์เรย์นับใช้ O(n) และหยุดได้ทันทีที่เจอค่าที่ผิด
