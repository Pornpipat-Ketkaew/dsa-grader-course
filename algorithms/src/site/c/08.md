## Toolkit for this chapter

### 1. One binary search template for everything

Every search here looks for a **boundary**: a yes/no question that is "yes, yes, …, yes, no, …, no" (or the reverse) along a sorted range. Keep two indices with an invariant:

```cpp
int left = -1, right = n;              // imaginary ends: left is "yes", right is "no"
while (right - left > 1) {
    int middle = left + (right - left) / 2;
    if (yes(middle)) left = middle; else right = middle;
}
// left = last "yes", right = first "no"
```

No `±1`, no special case for "not found": left = −1 or right = n say it.

### 2. Which comparison? (duplicates)

| you want | question | library |
|---|---|---|
| first value ≥ x | A[i] < x | `lower_bound(x)` |
| first value > x | A[i] ≤ x | `upper_bound(x)` |
| last value ≤ x | A[i] ≤ x, take left | `upper_bound(x) − 1` |
| how many in [lo, hi] | | `upper_bound(hi) − lower_bound(lo)` |

### 3. Binary search on the answer

If you cannot compute the answer but can **check** a guess, and the check is monotone ("if t works, every bigger t works"), search over the answer values. Cost = check × log(range). See Restaurant.

### 4. Prefix sums

`before[i] = A[0] + … + A[i−1]` makes any range sum O(1): `before[r+1] − before[l]`. With non-negative terms, `before` is sorted, so "how far until the sum passes a limit" is itself a binary search (Lawn Mowing, Saving for Ice Cream, Huge Array).

### How to recognise these problems

- Many queries about one fixed set → sort once (or build prefix sums once), then O(log n) per query.
- Huge sizes (10⁹, 10¹², 10¹⁸) that cannot be simulated → count instead, then search.
- "Next / previous / latest before" → successor / predecessor search, often after encoding the key as one number.

## ชุดเครื่องมือของบทนี้

### 1. แม่แบบ binary search เดียวใช้ได้ทุกข้อ

การค้นหาทุกข้อในบทนี้หา **รอยต่อ**: คำถามใช่/ไม่ใช่ที่เป็น "ใช่, ใช่, …, ใช่, ไม่, …, ไม่" (หรือกลับกัน) ตามช่วงที่เรียงแล้ว ใช้ดัชนีสองตัวกับเงื่อนไขคงที่:

```cpp
int left = -1, right = n;              // ปลายสมมติ: left คือ "ใช่", right คือ "ไม่"
while (right - left > 1) {
    int middle = left + (right - left) / 2;
    if (yes(middle)) left = middle; else right = middle;
}
// left = "ใช่" ตัวสุดท้าย, right = "ไม่" ตัวแรก
```

ไม่มี `±1` ไม่มีกรณีพิเศษ "หาไม่เจอ": left = −1 หรือ right = n บอกเอง

### 2. ใช้การเปรียบเทียบแบบไหน? (ค่าซ้ำ)

| ต้องการ | คำถาม | ไลบรารี |
|---|---|---|
| ค่าแรกที่ ≥ x | A[i] < x | `lower_bound(x)` |
| ค่าแรกที่ > x | A[i] ≤ x | `upper_bound(x)` |
| ค่าสุดท้ายที่ ≤ x | A[i] ≤ x แล้วเอา left | `upper_bound(x) − 1` |
| มีกี่ตัวใน [lo, hi] | | `upper_bound(hi) − lower_bound(lo)` |

### 3. Binary search บนคำตอบ

ถ้าคำนวณคำตอบตรง ๆ ไม่ได้ แต่ **ตรวจ** ค่าที่เดาได้ และการตรวจเป็นทางเดียว ("ถ้า t ใช้ได้ ทุก t ที่มากกว่าก็ใช้ได้") ให้ค้นบนค่าของคำตอบ ต้นทุน = การตรวจ × log(ช่วง) ดู Restaurant

### 4. ผลรวมสะสม

`before[i] = A[0] + … + A[i−1]` ทำให้ผลรวมช่วงใด ๆ เป็น O(1): `before[r+1] − before[l]` เมื่อพจน์ไม่ติดลบ `before` เรียงอยู่แล้ว "ไปได้ไกลแค่ไหนก่อนผลรวมเกินขีด" จึงเป็น binary search อีกที (Lawn Mowing, Saving for Ice Cream, Huge Array)

### วิธีสังเกตโจทย์แบบนี้

- คำถามจำนวนมากบนเซตเดียว → เรียงครั้งเดียว (หรือสร้างผลรวมสะสมครั้งเดียว) แล้ว O(log n) ต่อคำถาม
- ขนาดมหาศาล (10⁹, 10¹², 10¹⁸) ที่จำลองไม่ได้ → นับแทน แล้วค้นหา
- "ถัดไป / ก่อนหน้า / ล่าสุดก่อน" → หาตัวถัดไป / ตัวก่อนหน้า มักหลังเข้ารหัสคีย์เป็นตัวเลขเดียว
