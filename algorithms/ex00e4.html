ex00e4

Generate Barcodeสร้างบาร์โค้ด (Generate Barcode)

Backtracking (combinations)Feasibility pruningBacktracking (การจัดหมู่)ตัดกิ่งที่เป็นไปไม่ได้O(C(B, A) · B) time · O(B) memory (+ output)★☆☆

Decide the B characters left to right; at each position try '0' and '1', but only if the remaining positions can still end with exactly A ones. Every leaf of the pruned tree is a valid barcode.

ตัดสินใจตัวอักษร B ตัวจากซ้ายไปขวา ที่แต่ละตำแหน่งลอง '0' และ '1' แต่เฉพาะเมื่อตำแหน่งที่เหลือยังจบด้วย 1 จำนวน A ตัวพอดีได้ ทุกใบของต้นไม้ที่ตัดกิ่งแล้วคือบาร์โค้ดที่ถูกต้อง

1Technique: backtracking with a feasibility test

Backtracking builds an answer one decision at a time. The recursion depth is "how many decisions are made"; each call tries every choice for the next decision, recurses, and the choice is overwritten (undone) by the next try.

void generate(int position, state) {
    if (position == length) { record the answer; return; }
    for (each choice c that can still lead to an answer) {
        apply c at position;
        generate(position + 1, state after c);
        // the next loop iteration overwrites c: that is the "undo"
    }
}

The art is the condition "can still lead to an answer". If it is exact, the recursion never enters a dead branch, and the running time is proportional to the number of answers.

2How it maps onto this problem

The decision tree

A barcode is B characters. Decide them left to right: depth position = number of characters fixed. The state we need is just onesUsed (how many '1's so far).

The exact pruning rule

With placesLeft = B − position cells still empty and onesLeft = A − onesUsed ones still to place:

choice allowed when why
'0' onesLeft ≤ placesLeft − 1 after this '0', the other placesLeft − 1 cells must hold all remaining ones
'1' onesLeft > 0 do not exceed A ones

Both conditions are necessary and sufficient: if a choice is allowed, some completion exists (fill the rest with exactly the needed ones). So every branch we enter ends in a valid barcode, there are no dead ends, and no final check is needed at the leaf.

A = 1, B = 3                    root  (position 0, onesUsed 0)
                         ┌────────┴────────┐
                        '0'               '1'
                   ┌─────┴─────┐            │ onesLeft = 0 → only '0'
                  '0'         '1'          '0'
                   │ need 1 in 1 cell       │
                  '1'          '0'         '0'
                  001          010         100

Because '0' is tried before '1', the codes come out in increasing binary order. The statement accepts any order, but a deterministic order is easier to check.

Output

C(20, 10) = 184 756 lines of 21 characters ≈ 3.9 MB. Append everything to one string and print it once (or use fast I/O and '\n').

Traps
  • Generating all 2^B strings and filtering by popcount: 2²⁰ ≈ 10⁶ strings × 20 bits works here, but it is the habit the pruning teaches you to avoid (it explodes for "A of 40").
  • A = 0 must print one line of B zeros, and A = B = 0 prints one empty line.

3Solution

main.cpp⬇ .cpp
#include <iostream>
#include <string>
using namespace std;

int onesWanted, length;
string barcode;      // the code being built; position p is decided at recursion depth p
string output;       // every answer, printed once at the end

// position = number of characters already decided (barcode[0..position-1])
// onesUsed = how many of them are '1'
void generate(int position, int onesUsed) {
    if (position == length) {            // a full code; the pruning guarantees onesUsed == onesWanted
        output += barcode;
        output += '\n';
        return;
    }
    int placesLeft = length - position;
    int onesLeft = onesWanted - onesUsed;
    // choice '0': allowed only if the remaining placesLeft-1 cells can still hold every needed '1'
    if (onesLeft <= placesLeft - 1) {
        barcode[position] = '0';
        generate(position + 1, onesUsed);
    }
    // choice '1': allowed only if a '1' is still needed
    if (onesLeft > 0) {
        barcode[position] = '1';
        generate(position + 1, onesUsed + 1);
    }
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> onesWanted >> length;
    barcode.assign(length, '0');
    generate(0, 0);
    cout << output;
}

Complexity. No dead branches: the tree has C(B, A) leaves and depth B, so at most B · C(B, A) calls, plus the output itself. Memory: recursion depth B plus the output buffer.

1เทคนิค: backtracking พร้อมการตรวจว่ายังเป็นไปได้

Backtracking สร้างคำตอบทีละการตัดสินใจ ความลึกของ recursion คือ "ตัดสินใจไปแล้วกี่ครั้ง" แต่ละการเรียกลองทุกตัวเลือกของการตัดสินใจถัดไป เรียกตัวเองลึกลงไป แล้วตัวเลือกนั้นจะถูกเขียนทับ (ย้อนกลับ) ด้วยการลองครั้งถัดไป

void generate(int position, state) {
    if (position == length) { record the answer; return; }
    for (each choice c that can still lead to an answer) {
        apply c at position;
        generate(position + 1, state after c);
        // the next loop iteration overwrites c: that is the "undo"
    }
}

ศิลปะอยู่ที่เงื่อนไข "ยังไปถึงคำตอบได้" ถ้าเงื่อนไขแม่นยำ recursion จะไม่เข้ากิ่งตายเลย และเวลาที่ใช้จะแปรผันตามจำนวนคำตอบ

2นำมาใช้กับโจทย์นี้อย่างไร

ต้นไม้การตัดสินใจ

บาร์โค้ดมี B ตัวอักษร ตัดสินใจจากซ้ายไปขวา: ความลึก position = จำนวนตัวที่กำหนดแล้ว สถานะที่ต้องรู้มีแค่ onesUsed (ใช้ '1' ไปแล้วกี่ตัว)

กฎตัดกิ่งที่แม่นยำ

เมื่อยังเหลือช่องว่าง placesLeft = B − position ช่อง และต้องวางเลข 1 อีก onesLeft = A − onesUsed ตัว:

ตัวเลือก อนุญาตเมื่อ เหตุผล
'0' onesLeft ≤ placesLeft − 1 หลังวาง '0' นี้ ช่องที่เหลือ placesLeft − 1 ช่องต้องรับเลข 1 ที่เหลือทั้งหมด
'1' onesLeft > 0 ไม่ให้เกิน A ตัว

ทั้งสองเงื่อนไข จำเป็นและเพียงพอ: ถ้าตัวเลือกใดผ่าน ย่อมมีวิธีเติมที่เหลือให้ครบ (เติมเลข 1 เท่าที่ต้องการพอดี) ทุกกิ่งที่เข้าไปจึงจบด้วยบาร์โค้ดที่ถูกต้อง ไม่มีทางตัน และไม่ต้องตรวจซ้ำที่ใบ

A = 1, B = 3                    root  (position 0, onesUsed 0)
                         ┌────────┴────────┐
                        '0'               '1'
                   ┌─────┴─────┐            │ onesLeft = 0 → ได้แค่ '0'
                  '0'         '1'          '0'
                   │ ต้องมี 1 ใน 1 ช่อง      │
                  '1'          '0'         '0'
                  001          010         100

เพราะลอง '0' ก่อน '1' รหัสจึงออกมาเรียงจาก น้อยไปมาก ในฐานสอง โจทย์รับลำดับใดก็ได้ แต่ลำดับที่แน่นอนตรวจง่ายกว่า

การพิมพ์ผล

C(20, 10) = 184 756 บรรทัด บรรทัดละ 21 ตัวอักษร ≈ 3.9 MB ต่อทุกอย่างลง string เดียวแล้วพิมพ์ครั้งเดียว (หรือใช้ fast I/O กับ '\n')

กับดัก
  • สร้างทั้ง 2^B สตริงแล้วกรองด้วยจำนวนบิต 1: 2²⁰ ≈ 10⁶ สตริง × 20 บิตยังผ่านในข้อนี้ แต่เป็นนิสัยที่การตัดกิ่งสอนให้เลี่ยง (ระเบิดทันทีถ้าเป็น "A จาก 40")
  • A = 0 ต้องพิมพ์ศูนย์ B ตัวหนึ่งบรรทัด และ A = B = 0 พิมพ์บรรทัดว่างหนึ่งบรรทัด
