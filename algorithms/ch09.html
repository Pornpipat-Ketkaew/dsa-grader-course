1Toolkit for this chapter

Why sort, count or hash first

Many questions are hard on raw data and trivial once equal things are together or looked up in O(1):

tool use when cost
sort you need order, neighbours, groups of equal values, or binary search later O(n log n)
counting array count[value] values are small integers (≤ 10⁶ or so) O(n + range)
hash map unordered_map keys are large or sparse, only equality matters O(1) average per operation
ordered set / map you need order and updates O(log n) per operation

Counting tricks

  • Pigeonhole: n values in the range 1..n are all different iff every count is exactly 1.
  • Inversions (pairs out of order) = number of swaps insertion sort makes; count them with a Fenwick tree in O(n log n).
  • Cycle decomposition: the minimum swaps to sort is (elements out of place) − (number of cycles); with 3 values, fix 2-cycles first (one swap each), then 3-cycles (two swaps each).

How to recognise these problems

  • "How many times / which appears most / are they all different" → count.
  • "Is x in the set" with many queries → sort + binary search, or hash.
  • "Sort with the fewest swaps / count the moves of a sort" → inversions or cycles.

1ชุดเครื่องมือของบทนี้

ทำไมต้องเรียง นับ หรือแฮชก่อน

หลายคำถามยากบนข้อมูลดิบ แต่ง่ายมากเมื่อสิ่งที่เท่ากัน อยู่ด้วยกัน หรือ ค้นได้ใน O(1):

เครื่องมือ ใช้เมื่อ ต้นทุน
เรียง ต้องการลำดับ เพื่อนบ้าน กลุ่มของค่าที่เท่ากัน หรือ binary search ภายหลัง O(n log n)
อาร์เรย์นับ count[value] ค่าเป็นจำนวนเต็มเล็ก (ราว ≤ 10⁶) O(n + ช่วง)
hash map unordered_map คีย์ใหญ่หรือกระจาย และสนใจแค่การเท่ากัน O(1) โดยเฉลี่ยต่อครั้ง
ordered set / map ต้องการลำดับ และ การแก้ไข O(log n) ต่อครั้ง

เทคนิคการนับ

  • หลักรังนกพิราบ: ค่า n ตัวในช่วง 1..n ต่างกันทั้งหมดก็ต่อเมื่อทุกค่านับได้ 1 พอดี
  • Inversion (คู่ที่สลับลำดับ) = จำนวนการสลับที่ insertion sort ทำ นับด้วย Fenwick tree ใน O(n log n)
  • แยกเป็นวงรอบ: จำนวนการสลับน้อยที่สุดเพื่อเรียง = (ตัวที่อยู่ผิดที่) − (จำนวนวงรอบ) เมื่อมี 3 ค่า แก้วงรอบขนาด 2 ก่อน (สลับครั้งเดียว) แล้วค่อยวงรอบขนาด 3 (สลับสองครั้ง)

วิธีสังเกตโจทย์แบบนี้

  • "กี่ครั้ง / อะไรปรากฏมากที่สุด / ต่างกันทั้งหมดไหม" → นับ
  • "x อยู่ในเซตไหม" หลายคำถาม → เรียง + binary search หรือแฮช
  • "เรียงด้วยการสลับน้อยที่สุด / นับการย้ายของการเรียง" → inversion หรือวงรอบ
