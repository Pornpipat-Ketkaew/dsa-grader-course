ex00e5

Consecutive Onesเลข 1 ติดกัน (Consecutive Ones)

Backtracking over bit stringsState carried in parametersBacktracking บนสตริงบิตส่งสถานะผ่านพารามิเตอร์O(2ⁿ) time · O(n) memory (+ output)★☆☆

Enumerate all n-bit strings in increasing order ('0' before '1' at every depth) and carry two small facts down the recursion: the length of the current run of 1s and whether a run of k was already seen.

ไล่ทุกสตริง n บิตตามลำดับจากน้อยไปมาก ('0' ก่อน '1' ทุกระดับ) และส่งข้อมูลเล็ก ๆ สองอย่างลงไปใน recursion: ความยาวของเลข 1 ที่ติดกันอยู่ตอนนี้ และเคยเจอ 1 ติดกัน k ตัวแล้วหรือยัง

1Technique: enumerate in order, carry the state down

Two backtracking habits:

  1. Order for free. If every level tries '0' before '1', the leaves come out in increasing numeric order (that is just how binary counting works). No sorting is needed.
  2. Carry state as parameters. Instead of re-scanning the finished string at the leaf (O(n) per leaf), pass down what the check needs, updated in O(1) per step.

2How it maps onto this problem

What the check needs

"Contains at least k consecutive 1s" can be decided left to right with two numbers:

  • currentRun = length of the block of 1s that ends at the last decided bit;
  • found = whether some block already reached length k.
next bit new currentRun new found
'0' 0 unchanged
'1' currentRun + 1 found or currentRun + 1 ≥ k

Once found becomes true it stays true, and at the leaf we print the string iff found.

n = 4, k = 2      bits   run  found
                  0      0    no
                  01     1    no
                  011    2    YES  ← reached k: every extension of 011 qualifies
                  0110   0    yes  → printed
k = 0

"At least 0 consecutive ones" is always true, so found starts as k == 0. Then even n = 0 prints one (empty) line.

Could we prune?

Unlike the barcode problem, there is no dead end to cut: any prefix can still be extended with k ones if enough positions remain, and once found is true every extension is printed. A pruning like "not found and fewer than k − currentRun positions left → stop" is valid and saves some calls, but the output itself can be close to 2ⁿ lines, so the enumeration is already proportional to the answer in the worst case.

Traps
  • Printing in the wrong order: the statement requires increasing values. Try '0' first.
  • Checking only the final run (currentRun ≥ k at the leaf) misses strings like 1100.
  • The PDF's third sample is missing 11100; trust the definition.

3Solution

main.cpp⬇ .cpp
#include <iostream>
#include <string>
using namespace std;

int length, runNeeded;
string bits;         // the n-bit string being built
string output;       // up to 2^20 lines, printed once at the end

// position   = number of bits already decided (bits[0..position-1])
// currentRun = length of the block of '1's ending at position-1 (0 if that bit is '0')
// found      = did bits[0..position-1] already contain runNeeded consecutive '1's?
void generate(int position, int currentRun, bool found) {
    if (position == length) {
        if (found) { output += bits; output += '\n'; }
        return;
    }
    // '0' before '1' at every position = increasing numeric order of the whole string
    bits[position] = '0';
    generate(position + 1, 0, found);                       // a '0' breaks the run
    bits[position] = '1';
    generate(position + 1, currentRun + 1, found || currentRun + 1 >= runNeeded);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> length >> runNeeded;
    bits.assign(length, '0');
    generate(0, 0, runNeeded == 0);      // k = 0: every string qualifies
    cout << output;
}

Complexity. The full binary tree has 2ⁿ leaves and 2ⁿ⁺¹ − 1 calls, O(1) each: O(2ⁿ) ≈ 2·10⁶ for n = 20, plus the output. Memory: depth n.

1เทคนิค: ไล่ตามลำดับ แล้วส่งสถานะลงไป

นิสัยสองอย่างของ backtracking:

  1. ได้ลำดับฟรี ถ้าทุกระดับลอง '0' ก่อน '1' ใบจะออกมาเรียงจากน้อยไปมาก (นั่นคือวิธีนับเลขฐานสองนั่นเอง) ไม่ต้องเรียงทีหลัง
  2. ส่งสถานะเป็นพารามิเตอร์ แทนที่จะสแกนสตริงที่เสร็จแล้วที่ใบ (O(n) ต่อใบ) ให้ส่งสิ่งที่การตรวจต้องใช้ลงไป และอัปเดตด้วย O(1) ต่อขั้น

2นำมาใช้กับโจทย์นี้อย่างไร

การตรวจต้องรู้อะไร

"มีเลข 1 ติดกันอย่างน้อย k ตัว" ตัดสินได้จากซ้ายไปขวาด้วยตัวเลขสองตัว:

  • currentRun = ความยาวก้อนเลข 1 ที่จบที่บิตล่าสุดที่ตัดสินแล้ว
  • found = เคยมีก้อนที่ยาวถึง k แล้วหรือยัง
บิตถัดไป currentRun ใหม่ found ใหม่
'0' 0 เท่าเดิม
'1' currentRun + 1 found หรือ currentRun + 1 ≥ k

เมื่อ found เป็นจริงแล้วจะจริงตลอดไป และที่ใบเราพิมพ์สตริงเมื่อ found เป็นจริงเท่านั้น

n = 4, k = 2      bits   run  found
                  0      0    ไม่
                  01     1    ไม่
                  011    2    ใช่  ← ถึง k แล้ว: ทุกการต่อจาก 011 ผ่านหมด
                  0110   0    ใช่  → พิมพ์
k = 0

"มีเลข 1 ติดกันอย่างน้อย 0 ตัว" จริงเสมอ found จึงเริ่มเป็น k == 0 แม้ n = 0 ก็พิมพ์หนึ่งบรรทัด (ว่าง)

ตัดกิ่งได้ไหม?

ต่างจากโจทย์บาร์โค้ด ข้อนี้ไม่มีทางตันให้ตัด: prefix ใดก็ยังต่อด้วยเลข 1 k ตัวได้ถ้าเหลือตำแหน่งพอ และเมื่อ found จริงแล้วทุกการต่อจะถูกพิมพ์ การตัดแบบ "ยังไม่เจอและเหลือตำแหน่งน้อยกว่า k − currentRun → หยุด" ถูกต้องและลดการเรียกได้บ้าง แต่ผลลัพธ์เองอาจใกล้ 2ⁿ บรรทัด การไล่ทั้งหมดจึงแปรผันตามขนาดคำตอบอยู่แล้วในกรณีแย่สุด

กับดัก
  • พิมพ์ผิดลำดับ: โจทย์ต้องการเรียงจากน้อยไปมาก ให้ลอง '0' ก่อน
  • ตรวจเฉพาะก้อน สุดท้าย (currentRun ≥ k ที่ใบ) จะพลาดสตริงอย่าง 1100
  • ตัวอย่างที่สามใน PDF ขาด 11100 ให้เชื่อนิยาม
