## 1. What the problem says
A directed graph has n nodes (0..n−1, n ≤ 5,000) and m weighted edges (m ≤ 100,000). Weights are between −1,000 and 1,000 and **may be negative**, but no cycle has a negative total. You may start at any of k given nodes and want to reach the goal v. Print the **shortest distance from any start to v**. At least one start can reach v.

Input: `n m k`, then v, then the k start nodes, then m lines `a b w` (edge a → b).

Sample 2: goal 5, starts 4 3 0 1 → **−2** (3 → 2 → 5 costs 2 + (−4)). Sample 1 → **2**.

## 2. What it really means
"Shortest from **any** of several starts" is one shortest-path problem from a single **super-source** S that has a 0-weight edge to every start. There is no need to build S: just set dist = 0 for all starts before the algorithm begins. Because weights can be negative, Dijkstra is not safe; **Bellman–Ford** is.

```text
starts (distance 0): 0, 1, 3, 4            goal: 5

 0 ──10──► 1 ──8──► 4
           │ ╲
           5   7
           │     ╲
           ▼       ▼
           2 ◄──2── 3
           │
          -4
           ▼
           5

from 1:  1 → 2 → 5  =  5 − 4  =  1
from 3:  3 → 2 → 5  =  2 − 4  = −2   ← best
```

:::hint Hint 1
How would you handle "start anywhere among these k nodes" if there were only one start? Add one imaginary node that reaches all k starts for free.
:::
:::hint Hint 2
Some edges are negative, so use Bellman–Ford: set dist = 0 for every start, INF elsewhere, then relax all edges round after round. Stop early when a whole round changes nothing; n − 1 rounds is the maximum.
:::

## 3. What, why, how
- **What:** multi-source Bellman–Ford with an early stop.
- **Why initialising all starts to 0 is right:** it is exactly the state after relaxing the edges S → start in the first round of a run from S. Everything after that is ordinary Bellman–Ford, so dist[x] ends as the minimum over starts of the distance start → x.
- **Why not Dijkstra:** it fixes a node's distance when the node is taken from the queue, assuming no later path can be cheaper. A negative edge breaks that assumption: in sample 2, node 2 would be fixed at 5 (via 1) before 3 → 2 with weight 2 is seen.
- **How:**
  - Store edges in an array of (a, b, w).
  - Repeat up to n − 1 rounds: for every edge with dist[a] ≠ INF, if dist[a] + w < dist[b] then improve dist[b] and remember that something changed. If nothing changed, stop.
  - Print dist[v].
- **Why n − 1 rounds suffice:** with no negative cycle a shortest path is simple, so it has at most n − 1 edges, and round r fixes every shortest path of r edges.
- **Cost:** worst case (n − 1) · m = 5 × 10⁸ simple steps, but the early stop usually ends after a few rounds. Even our worst-order chain (about n rounds) took 0.16 s.

## 5. Traps
- **Relaxing from INF:** `INF + (−4)` is still "infinite" but smaller than INF, and can spread garbage. Skip edges whose start is unreachable.
- **Running Bellman–Ford once per start:** k · n · m = 2.5 × 10¹² in the worst case. One multi-source run is enough.
- **Reversing the graph and starting from v** also works (then take the minimum over the starts), but it is easy to forget to reverse the edge directions.
- **Dijkstra "because the graph has no negative cycle":** no negative cycle is not the same as no negative edge.
- **Input size:** 100,000 edge lines; use `ios_base::sync_with_stdio(false)` as the PDF says.

"สั้นที่สุดจากจุดเริ่ม **ใดก็ได้** ในหลายจุด" คือปัญหาเส้นทางสั้นสุดปัญหาเดียวจาก **super-source** S ที่มีเส้นน้ำหนัก 0 ไปยังทุกจุดเริ่ม ไม่ต้องสร้าง S จริง แค่ตั้ง dist = 0 ให้ทุกจุดเริ่มก่อนเริ่มอัลกอริทึม และเพราะน้ำหนักติดลบได้ Dijkstra จึงไม่ปลอดภัย ต้องใช้ **Bellman–Ford**

           │ ╲
           5   7
           │     ╲
           ▼       ▼
           2 ◄──2── 3
           │
          -4
           ▼
           5

## 3. อะไร ทำไม อย่างไร
- **อะไร:** Bellman–Ford แบบหลายจุดเริ่ม พร้อมหยุดก่อนกำหนด
- **ทำไมตั้งทุกจุดเริ่มเป็น 0 ถึงถูก:** มันคือสถานะหลัง relax เส้น S → จุดเริ่ม ในรอบแรกของการรันจาก S พอดี หลังจากนั้นก็เป็น Bellman–Ford ธรรมดา dist[x] ตอนจบจึงเป็นค่าน้อยสุดของระยะ จุดเริ่ม → x ในทุกจุดเริ่ม
- **ทำไมไม่ใช้ Dijkstra:** Dijkstra ปักระยะของปมตอนดึงออกจากคิว โดยเชื่อว่าไม่มีเส้นทางหลังจากนั้นที่ถูกกว่า เส้นติดลบทำลายความเชื่อนี้: ในตัวอย่างที่ 2 ปม 2 จะถูกปักที่ 5 (ผ่าน 1) ก่อนจะเห็น 3 → 2 น้ำหนัก 2
- **อย่างไร:**
  - เก็บเส้นเป็นอาเรย์ของ (a, b, w)
  - ทำซ้ำไม่เกิน n − 1 รอบ: ทุกเส้นที่ dist[a] ≠ INF ถ้า dist[a] + w < dist[b] ให้ปรับ dist[b] และจำว่ามีการเปลี่ยน ถ้าไม่มีอะไรเปลี่ยนให้หยุด
  - พิมพ์ dist[v]
- **ทำไม n − 1 รอบพอ:** เมื่อไม่มีวงลบ เส้นทางสั้นที่สุดเป็น simple path จึงมีไม่เกิน n − 1 เส้น และรอบที่ r ทำให้ทุกเส้นทางสั้นสุดที่มี r เส้นถูกต้อง
- **ต้นทุน:** แย่สุด (n − 1) · m = 5 × 10⁸ ขั้นง่าย ๆ แต่การหยุดก่อนมักจบในไม่กี่รอบ แม้แต่โซ่ที่เรียงแย่ที่สุดของเรา (ราว n รอบ) ก็ใช้ 0.16 วินาที

## 5. จุดที่มักพลาด
- **relax จาก INF:** `INF + (−4)` ยังเป็น "อนันต์" แต่น้อยกว่า INF และอาจกระจายค่าขยะไปทั่ว ให้ข้ามเส้นที่ปมต้นทางยังไปไม่ถึง
- **รัน Bellman–Ford ทีละจุดเริ่ม:** k · n · m = 2.5 × 10¹² ในกรณีแย่สุด รันแบบหลายจุดเริ่มครั้งเดียวพอ
- **กลับทิศกราฟแล้วเริ่มจาก v** ก็ใช้ได้ (แล้วเอาค่าน้อยสุดบนจุดเริ่ม) แต่ลืมกลับทิศเส้นได้ง่าย
- **ใช้ Dijkstra "เพราะกราฟไม่มีวงลบ":** ไม่มีวงลบ ไม่ได้แปลว่าไม่มีเส้นลบ
- **ขนาด input:** 100,000 บรรทัด ใช้ `ios_base::sync_with_stdio(false)` ตามที่ PDF บอก
