## 1. What the problem says
T graphs (T ≤ 100). Each has N vertices (0..N−1, N ≤ 1,000) and E edges (1 ≤ E ≤ 10,000), undirected and simple. For each graph print `YES` if it contains a cycle, otherwise `NO`.

Sample: (4 nodes, 0 edges) → NO; (triangle 0-1-2 plus edge 2-3) → YES; (triangle plus node 3) → YES; (single edge 1-3) → NO.

## 2. What it really means
A graph has **no** cycle exactly when it is a forest. Build the graph edge by edge and watch the pieces merge:

```text
edge 2-3:  {2,3}            pieces: {0} {1} {2,3}
edge 0-1:  {0,1}            pieces: {0,1} {2,3}
edge 1-2:  joins them       pieces: {0,1,2,3}
edge 2-0:  2 and 0 are ALREADY in the same piece  →  this edge closes a cycle
```

:::hint Hint 1
An edge (a, b) creates a cycle exactly when a and b were already connected before the edge was added.
:::
:::hint Hint 2
Keep "which piece is each vertex in" with a union-find (disjoint-set) structure: `find(x)` gives the piece's representative, `parent[ra] = rb` merges two pieces.
:::

## 3. What, why, how
- **What:** cycle detection in an undirected graph with DSU.
- **Why it is correct:** if a and b are already connected by a path P, then P + (a, b) is a cycle. If they are not connected, the new edge only joins two separate trees, which never creates a cycle. So a cycle exists iff at least one edge finds its ends in the same set.
- **How:**
  1. `parent[i] = i` for every vertex (each vertex alone);
  2. for each edge: ra = find(a), rb = find(b); equal → cycle; otherwise `parent[ra] = rb`.
- **Path compression** (`parent[x] = find(parent[x])`) keeps the trees almost flat, so each find is practically O(1).
- **Read every edge even after a cycle is found**: the next graph starts after the last edge line.
- **DFS alternative:** run DFS and look for an edge to an already-visited vertex **that is not the parent** you came from. It works too, but the parent check is an easy place to make mistakes; DSU has no such subtlety. A third way: a graph is a forest iff E = N − (number of components).

## 5. Traps
- **Stopping to read when a cycle is found:** the remaining edge lines would be read as the next graph's N and E.
- **Treating the reverse direction as a cycle in DFS:** in an undirected graph, going back along the edge you came from is not a cycle.
- **Not resetting per graph:** `parent` must be re-initialised for every test case.
- **Isolated vertices:** they never matter for cycles (first sample: 4 vertices, 0 edges → NO; note the PDF says E ≥ 1 but the sample has E = 0, and the code handles it).

## 3. อะไร ทำไม อย่างไร
- **อะไร:** ตรวจวงวนในกราฟไม่มีทิศทางด้วย DSU
- **ทำไมถูก:** ถ้า a กับ b เชื่อมกันอยู่แล้วด้วยเส้นทาง P แล้ว P + (a, b) คือวงวน ถ้ายังไม่เชื่อมกัน เส้นใหม่แค่เชื่อมต้นไม้สองต้นที่แยกกัน ซึ่งไม่มีทางเกิดวงวน ดังนั้นมีวงวนก็ต่อเมื่อมีอย่างน้อยหนึ่งเส้นที่ปลายทั้งสองอยู่เซตเดียวกัน
- **อย่างไร:**
  1. `parent[i] = i` ทุกจุด (แต่ละจุดอยู่คนเดียว)
  2. ทุกเส้น: ra = find(a), rb = find(b) เท่ากัน → มีวงวน ไม่เท่า → `parent[ra] = rb`
- **Path compression** (`parent[x] = find(parent[x])`) ทำให้ต้นไม้แทบแบน find แต่ละครั้งจึงเกือบ O(1)
- **อ่านทุกเส้นให้ครบแม้เจอวงวนแล้ว**: กราฟถัดไปเริ่มหลังบรรทัดเส้นเชื่อมบรรทัดสุดท้าย
- **ทางเลือก DFS:** ทำ DFS แล้วหาเส้นที่ไปยังจุดที่เคยเยี่ยมแล้ว **ซึ่งไม่ใช่พ่อ** ที่เราเพิ่งเดินมา ใช้ได้เหมือนกัน แต่การเช็กพ่อเป็นจุดที่พลาดง่าย DSU ไม่มีความละเอียดอ่อนแบบนั้น วิธีที่สาม: กราฟเป็นป่าก็ต่อเมื่อ E = N − (จำนวน component)
