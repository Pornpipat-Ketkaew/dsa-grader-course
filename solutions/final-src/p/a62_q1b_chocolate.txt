## 1. What the problem says
A chocolate bar has n small pieces (2 ≤ n ≤ 10⁴). Every day we break off some pieces from one end and eat them; the number eaten on a day must belong to a set S (k ≤ 10 distinct values, 1 ∈ S, all ≤ n). We write down the daily amounts, e.g. [1, 2, 1, 2]. **How many different lists** finish the bar exactly? Print the count mod 1,000,003.

Example: n = 4, S = {1, 3} → [1,3], [3,1], [1,1,1,1] → **3**.

## 2. What it really means
We count **ordered** sums: sequences of numbers from S that add up to n ([1,3] and [3,1] are different). Look at the **last day**: it eats some s ∈ S, and before that we finished a bar of n − s pieces in any valid way.

```text
ways to finish 4 with S = {1,3}:
   last day 1  →  any way to finish 3  :  [1,1,1], [3]      → [1,1,1,1], [3,1]
   last day 3  →  any way to finish 1  :  [1]               → [1,3]
                                                               total 3
```

:::hint Hint 1
Let ways[i] = number of valid lists for a bar of i pieces. Write ways[i] in terms of smaller indices.
:::
:::hint Hint 2
ways[0] = 1 (the empty list). Then ways[i] = Σ ways[i − s] for every s ∈ S with s ≤ i. Fill i = 1, 2, …, n.
:::

## 3. What, why, how
- **What:** a counting DP over the amount left to eat.
- **Why the recurrence counts everything exactly once:** every list has a unique last element s, and removing it leaves a unique list for n − s. Different s give different lists, so the sum has no double counting.
- **Why ways[0] = 1:** a list that eats the whole bar on its last day (s = i) is "the empty list for 0, then s". It must count as 1.
- **How:** one loop over i = 1..n, an inner loop over the k sizes; n·k ≤ 10⁵ steps.
- **Mod:** keep every ways[i] < 1,000,003; adding two such numbers stays below 2·10⁶, no overflow.
- **Sanity check:** with S = {1, 2} the counts are 1, 1, 2, 3, 5, 8, …: Fibonacci again, and ways[10] = 89 is the second sample.

## 5. Traps
- **Counting unordered sums (partitions):** the problem treats [1,3] and [3,1] as different. If you loop "for each s, for each i" (the coin-change order) you count each multiset once and get the wrong answer (2 instead of 3 for the first sample).
- **ways[0] = 0:** then nothing is ever counted.
- **Mod only at the end:** the true counts grow exponentially and overflow long before n = 10⁴.
- **s > i:** skip those sizes (or the index goes negative).

## 6. Background
Lesson 14. "Number of ordered ways to reach a total with steps from a set" is the staircase / compositions DP. Swapping the two loops gives the coin-change (combinations) DP, which counts each multiset once: knowing which loop order counts which thing is a favourite exam question.

## 2. จริง ๆ แล้วถามอะไร
เรานับผลบวก **แบบมีลำดับ**: ลำดับตัวเลขจาก S ที่รวมกันได้ n ([1,3] กับ [3,1] นับเป็นคนละแบบ) ให้มองที่ **วันสุดท้าย**: กินไป s ∈ S ชิ้น และก่อนหน้านั้นเรากินแท่งขนาด n − s ให้หมดด้วยวิธีใดก็ได้

```text
ways to finish 4 with S = {1,3}:
   last day 1  →  any way to finish 3  :  [1,1,1], [3]      → [1,1,1,1], [3,1]
   last day 3  →  any way to finish 1  :  [1]               → [1,3]
                                                               total 3
```

:::hint คำใบ้ 1
ให้ ways[i] = จำนวนรายการที่ใช้ได้สำหรับแท่งขนาด i ชิ้น ลองเขียน ways[i] ในรูปของตำแหน่งที่เล็กกว่า
:::
:::hint คำใบ้ 2
ways[0] = 1 (รายการว่าง) แล้ว ways[i] = Σ ways[i − s] ทุก s ∈ S ที่ s ≤ i เติม i = 1, 2, …, n
:::

## 3. อะไร ทำไม อย่างไร
- **อะไร:** DP แบบนับ บนจำนวนชิ้นที่ยังเหลือ
- **ทำไมความสัมพันธ์นี้นับทุกแบบครั้งเดียวพอดี:** ทุกรายการมีตัวสุดท้าย s แบบเดียว ตัดออกแล้วเหลือรายการของ n − s แบบเดียว s ต่างกันให้รายการต่างกัน ผลรวมจึงไม่นับซ้ำ
- **ทำไม ways[0] = 1:** รายการที่วันสุดท้ายกินหมดทั้งแท่ง (s = i) คือ "รายการว่างของ 0 แล้วตามด้วย s" ต้องนับเป็น 1
- **อย่างไร:** ลูป i = 1..n หนึ่งชั้น และลูปข้างในวนขนาดทั้ง k ค่า รวม n·k ≤ 10⁵ ขั้น
- **mod:** ให้ ways[i] < 1,000,003 เสมอ บวกสองค่าแบบนี้ได้ไม่เกิน 2·10⁶ ไม่ล้น
- **เช็กความสมเหตุสมผล:** ถ้า S = {1, 2} จะได้ 1, 1, 2, 3, 5, 8, …: Fibonacci อีกแล้ว และ ways[10] = 89 คือตัวอย่างที่สอง

## 5. จุดที่มักพลาด
- **นับผลบวกแบบไม่สนลำดับ (partition):** โจทย์ถือว่า [1,3] กับ [3,1] ต่างกัน ถ้าวนลูป "ทุก s แล้วทุก i" (ลำดับแบบแลกเหรียญ) จะนับแต่ละ multiset ครั้งเดียวและได้คำตอบผิด (ตัวอย่างแรกได้ 2 แทน 3)
- **ways[0] = 0:** จะไม่มีอะไรถูกนับเลย
- **mod แค่ตอนจบ:** จำนวนจริงโตแบบเลขชี้กำลังและล้นก่อน n = 10⁴ ไปนาน
- **s > i:** ข้ามขนาดนั้นไป (ไม่เช่นนั้นตำแหน่งจะติดลบ)
