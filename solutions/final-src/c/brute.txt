## 1. The idea
**Brute force** means: list every candidate answer and check each one. It is the first solution to think of, and often the right one when the input is small (n ≤ 10 for permutations, n ≤ 20 for subsets).

**Backtracking** is brute force done carefully. Build the candidate one choice at a time (a decision tree), and **stop a branch as soon as it can no longer succeed** (pruning). The work then becomes proportional to the answers instead of to all candidates.

```text
           choose position 0
          /        |        \
    choose 1    choose 1   choose 1        each level = one decision
     / | \       / | \      / | \          a leaf = one complete candidate
   ...  ✗ ...   ...  ...   ✗  ...          ✗ = pruned: cannot lead to an answer
```

## 2. The template
```cpp
int n;
vector<int> cur;            // the partial answer, one entry per decided level
vector<bool> used;          // which values are taken (for permutations)

void gen(int pos) {
    if (pos == n) {         // every level decided: record or print the answer
        print(cur);
        return;
    }
    // try every choice for this level, in the order the output needs (smallest first)
    for (int v = 0; v < n; v++) {
        if (used[v] || !canPlace(v, pos)) continue;   // pruning: skip impossible branches
        used[v] = true;  cur[pos] = v;                // make the choice
        gen(pos + 1);                                 // decide the rest
        used[v] = false;                              // undo it (backtrack)
    }
}
```

Three parts: a **base case** that records the answer, a **loop over choices** in the required order, and **make / recurse / undo**.

## 3. How to recognise it
- "Print **all** …", "list every …", "in lexicographic / alphabetical order".
- Small limits: n ≤ 8–11 for permutations (n! up to 4 × 10⁷), n ≤ 20 for subsets or binary strings (2²⁰ ≈ 10⁶).
- The output itself is huge: then you **must** enumerate, and the only question is how fast you print.

## 4. Cost and pitfalls
- Without pruning: n! or 2ⁿ leaves times O(n) per leaf. With good pruning: about O(answers · n).
- **Order for free:** trying choices smallest-first gives lexicographic output, as long as no answer is a prefix of another.
- **Undo** every change after the recursive call (used[], visited cells, counters).
- **Output speed:** collect lines in a buffer or a `string`; never `endl` per line.
- **Recursion depth** equals the number of levels; fine for n ≤ 10⁴, dangerous beyond that.

## 1. ไอเดีย
**Brute force** คือ: แจกแจงทุกคำตอบที่เป็นไปได้แล้วตรวจทีละตัว เป็นวิธีแรกที่ควรนึกถึง และมักเป็นวิธีที่ถูกเมื่อ input เล็ก (n ≤ 10 สำหรับ permutation, n ≤ 20 สำหรับเซตย่อย)

**Backtracking** คือ brute force ที่ทำอย่างระวัง สร้างคำตอบทีละการตัดสินใจ (ต้นไม้การตัดสินใจ) และ **หยุดกิ่งทันทีที่รู้ว่าไปต่อไม่สำเร็จแน่** (การตัดกิ่ง หรือ pruning) งานที่ทำจะเป็นสัดส่วนกับจำนวนคำตอบ แทนที่จะเป็นจำนวนตัวเลือกทั้งหมด

```text
           choose position 0
          /        |        \
    choose 1    choose 1   choose 1        each level = one decision
     / | \       / | \      / | \          a leaf = one complete candidate
   ...  ✗ ...   ...  ...   ✗  ...          ✗ = pruned: cannot lead to an answer
```

มีสามส่วน: **กรณีฐาน** ที่บันทึกคำตอบ, **ลูปทางเลือก** ตามลำดับที่ผลลัพธ์ต้องการ และ **เลือก / เรียกซ้ำ / ย้อนคืน**

## 3. ดูอย่างไรว่าใช่
- "พิมพ์ **ทุก** …", "แจกแจงทุก …", "เรียงตามลำดับพจนานุกรม / ตัวอักษร"
- ขอบเขตเล็ก: n ≤ 8–11 สำหรับ permutation (n! ถึง 4 × 10⁷), n ≤ 20 สำหรับเซตย่อยหรือสตริงไบนารี (2²⁰ ≈ 10⁶)
- ผลลัพธ์ใหญ่มากเอง: แบบนี้ **ต้อง** แจกแจง คำถามเดียวคือพิมพ์ให้เร็วแค่ไหน

## 4. ต้นทุนและจุดพลาด
- ไม่ตัดกิ่ง: n! หรือ 2ⁿ ใบ คูณ O(n) ต่อใบ ตัดกิ่งดี: ราว O(จำนวนคำตอบ · n)
- **ได้ลำดับฟรี:** ลองทางเลือกจากน้อยไปมาก ผลลัพธ์จะเรียงตามพจนานุกรม ตราบที่ไม่มีคำตอบไหนเป็น prefix ของอีกคำตอบ
- **ย้อนคืน** ทุกการเปลี่ยนแปลงหลังเรียกซ้ำ (used[], ช่องที่เยี่ยมแล้ว, ตัวนับ)
- **ความเร็วการพิมพ์:** เก็บบรรทัดไว้ใน buffer หรือ `string` อย่าใช้ `endl` ทุกบรรทัด
- **ความลึกของ recursion** เท่ากับจำนวนชั้น n ≤ 10⁴ ไม่เป็นไร เกินนั้นอันตราย

## 5. ในบทนี้
- [Generate barcode](#ex00e4): สตริงฐานสองที่มีเลข 1 พอดี A ตัว ตัดกิ่งด้วยคำถาม "ยังมีที่เหลือไหม"
- [Consecutive ones](#ex00e5): ทุกสตริง n บิตตามลำดับ โดยพกความยาวของช่วงเลข 1 ปัจจุบันเป็น state เพิ่ม
- [n-Queen](#ex07e1_nqueen): ราชินีแถวละตัว เช็กการโจมตีใน O(1) ด้วยอาเรย์ bool สามตัว
- [Permutation with constraint](#a64_q1_permu_before): permutation ตามลำดับพจนานุกรมพร้อมกฎ "a มาก่อน b" ใช้อาเรย์ used[] และการเช็กเฉพาะจุด
- [Tower defense](#a65_q1_tower_defense): ป้อมแต่ละป้อมเลือกเป้า n ที่ใหญ่มากไม่มีผล แต่ k ที่เล็กมากเป็นตัวกำหนด
- [Day cover](#a66_q1a_day_cover): ลองทุกเซตย่อยของนิสิตไม่เกิน 20 คน (ชวนหรือข้าม) ด้วย bitset และตัดกิ่งด้วยคำตอบที่ดีที่สุดจนถึงตอนนี้
- [Path sum](#a64_q4_path_sum): ทุก simple path ในกราฟ 20 ปม ตัดด้วยขอบบนและการหยุดก่อน
- [Graph coloring](#ex07e3_coloring): branch and bound พร้อมการตัดสมมาตรและลำดับ DSATUR
