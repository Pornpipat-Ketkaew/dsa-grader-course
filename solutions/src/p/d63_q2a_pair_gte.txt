## 1. What the problem says
Override `operator>=` of CP::pair with these rules:

- a == b when both first and both second are equal.
- a > b when **a.first > b.first**, or **firsts equal and a.second > b.second**.
- `>=` must not modify either pair and **must not call pair's `operator<` or `operator==`** (they print "You cannot call …").
- Example: {5,"yes"} ≥ {1,"haha"} → true; {1,"haha"} ≥ {1,"haha"} → true; {9,"no"} ≥ {9,"zzz"} → false.

## 2. What it really means
**Lexicographic** (dictionary) order on two fields — the same order as `std::pair`. Comparing the *fields* (int, string) with `<` is fine; only the *pair's* operators are banned.

```text
compare first:   a.first > b.first → true     a.first < b.first → false
firsts tie  →  compare second:  a.second >= b.second ?
```

## 3. What, why, how
- With only `<` on the fields: "x > y" is `y < x`, and "x ≥ y" is `!(x < y)`.
- So: if `b.first < a.first` → true; if `a.first < b.first` → false; else return `!(a.second < b.second)`.
- Using only `<` means it works for any T1/T2 that has `<` (strings, ints, …).

## 5. Traps
- **Calling `*this < other` or `*this == other`** — forbidden, prints a message and loses marks.
- **`first >= other.first && second >= other.second`** is wrong: {2,"a"} ≥ {1,"z"} must be true (first decides alone).
- **Using `==` on the fields** is allowed, but writing the logic with only `<` is more general.

## 6. Background
Lesson 06: every ordering in C++ can be built from one `<` ("strict weak ordering"): `a > b ⇔ b < a`, `a ≥ b ⇔ !(a < b)`, `a == b ⇔ !(a<b) && !(b<a)`. Multi-key comparison is the same idea used in Custom Order and in heap comparators.

## 1. โจทย์บอกอะไร
override `operator>=` ของ CP::pair ตามกฎนี้:

- a == b เมื่อ first เท่ากันและ second เท่ากัน
- a > b เมื่อ **a.first > b.first** หรือ **first เท่ากันและ a.second > b.second**
- `>=` ต้องไม่แก้ข้อมูลของทั้งสองคู่ และ **ห้ามเรียก `operator<` หรือ `operator==` ของ pair** (มันจะพิมพ์ "You cannot call …")
- ตัวอย่าง: {5,"yes"} ≥ {1,"haha"} → true; {1,"haha"} ≥ {1,"haha"} → true; {9,"no"} ≥ {9,"zzz"} → false

## 2. จริง ๆ แล้วถามอะไร
ลำดับ **แบบพจนานุกรม** (lexicographic) บนสองฟิลด์ — แบบเดียวกับ `std::pair` การเทียบ *ฟิลด์* (int, string) ด้วย `<` ทำได้ ที่ห้ามคือ operator ของ *pair*

```text
compare first:   a.first > b.first → true     a.first < b.first → false
firsts tie  →  compare second:  a.second >= b.second ?
```

เหมือนเรียงชื่อในสมุดโทรศัพท์: ดูนามสกุลก่อน ถ้านามสกุลเหมือนกันค่อยดูชื่อ

## 3. อะไร ทำไม อย่างไร
- ถ้ามีแค่ `<` บนฟิลด์: "x > y" คือ `y < x` และ "x ≥ y" คือ `!(x < y)`
- ดังนั้น: ถ้า `b.first < a.first` → true; ถ้า `a.first < b.first` → false; ไม่อย่างนั้นคืน `!(a.second < b.second)`
- ใช้แค่ `<` ทำให้ใช้ได้กับ T1/T2 ใดก็ได้ที่มี `<` (string, int, …)
