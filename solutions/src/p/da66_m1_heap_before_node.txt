==== en
## 1. What the problem says
A binary heap in a vector (root 0, children 2i+1, 2i+2). Given the size n (1..500,000) and a slot m, print **which slots could possibly hold a value that is "higher"** — popped before the value in slot m — in increasing order. First line: the count; second line: the slots (empty line if none).

- m = 0 → nothing (the root is the top). n = 3, m = 1 → slots 0 and 2.

## 2. What it really means
"Could possibly" = in **some** valid heap. Which slots can never beat m?

- **m's descendants**: the heap property forces every descendant ≤ m.
- m itself.

Every other slot — m's ancestors **and** all nodes in other branches — can be bigger in some heap.

```text
n = 6, m = 4:            0
                      1     2
                    3  [4]  5        subtree of 4 = {4} (children 9,10 ≥ n)
answer: 0 1 2 3 5  (count 5)
```

## 3. What, why, how
- Mark the subtree of m level by level (same as Heap Descendant: [lo, hi] → [2lo+1, 2hi+2]).
- Print every unmarked index from 0 to n−1. O(n).
- Why are cousins possible? Put the biggest values along the path to any slot outside m's subtree — the heap property never compares that slot with m.

## 5. Traps
- **Answering only ancestors** (0, 1 for m = 4) — slots in other branches (2, 3, 5, …) can hold bigger values too.
- **Answering "all slots with a smaller index"** — slot 5 (index > 4) is in the answer, slot 9 is not.
- **Printing nothing on the second line**: when the count is 0, the second line must still exist (empty).

## 6. Background
Lesson 06: the heap property only orders **ancestor–descendant** pairs; nodes in different branches are unordered. So "certainly smaller" = descendant, "maybe bigger" = everything else.
==== th
## 1. โจทย์บอกอะไร
ไบนารีฮีปใน vector (ราก 0, ลูก 2i+1, 2i+2) ให้ขนาด n (1..500,000) และช่อง m ให้พิมพ์ **ช่องที่ "มีโอกาส" เก็บค่าที่ "สูงกว่า"** — ถูก pop ก่อนค่าในช่อง m — เรียงจากน้อยไปมาก บรรทัดแรกคือจำนวน บรรทัดที่สองคือหมายเลขช่อง (ถ้าไม่มีให้เป็นบรรทัดว่าง)

- m = 0 → ไม่มีเลย (รากคือ top) n = 3, m = 1 → ช่อง 0 และ 2

## 2. จริง ๆ แล้วถามอะไร
"มีโอกาส" = ใน **บางฮีป** ที่ถูกต้อง แล้วช่องไหนที่ไม่มีทางชนะ m?

- **ลูกหลานของ m**: คุณสมบัติฮีปบังคับให้ลูกหลานทุกตัว ≤ m
- m เอง

ช่องอื่นทั้งหมด — บรรพบุรุษของ m **และ** ทุกโหนดในกิ่งอื่น — ใหญ่กว่าได้ในบางฮีป

```text
n = 6, m = 4:            0
                      1     2
                    3  [4]  5        subtree of 4 = {4} (children 9,10 ≥ n)
answer: 0 1 2 3 5  (count 5)
```

เหมือนบริษัท: ลูกน้องใต้สายของคุณเงินเดือนไม่เกินคุณแน่นอน แต่หัวหน้าของคุณ และคนในแผนกอื่น อาจได้มากกว่าคุณก็ได้

## 3. อะไร ทำไม อย่างไร
- ทำเครื่องหมายต้นไม้ย่อยของ m ทีละชั้น (เหมือนข้อ Heap Descendant: [lo, hi] → [2lo+1, 2hi+2])
- พิมพ์ทุก index ที่ไม่ถูกทำเครื่องหมายตั้งแต่ 0 ถึง n−1 เวลา O(n)
- ทำไมญาติกิ่งอื่นเป็นไปได้? วางค่ามาก ๆ ไว้ตามเส้นทางไปยังช่องที่อยู่นอกต้นไม้ย่อยของ m — คุณสมบัติฮีปไม่เคยเทียบช่องนั้นกับ m เลย

## 5. จุดที่มักพลาด
- **ตอบแค่บรรพบุรุษ** (0, 1 สำหรับ m = 4) — ช่องในกิ่งอื่น (2, 3, 5, …) ก็ใหญ่กว่าได้
- **ตอบ "ทุกช่องที่ index น้อยกว่า"** — ช่อง 5 (index > 4) อยู่ในคำตอบ แต่ช่อง 9 ไม่อยู่
- **ไม่พิมพ์บรรทัดที่สอง**: ถ้าจำนวนเป็น 0 ยังต้องมีบรรทัดที่สอง (ว่าง)
