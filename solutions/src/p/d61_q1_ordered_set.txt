## 1. What the problem says
An **ordered set** is a list with no repeats where order matters (stored in `std::vector`). Write:

- `Union(A,B)`: everything in A or B, and **A's items come before items only in B**. `Union(<4,6,9,0,7>, <0,3,2,4,5>) = <4,6,9,0,7,3,2,5>`.
- `Intersect(A,B)`: items in both, **in A's order**. `Intersect(<3,9,0,1,6>, <4,6,9,1,7>) = <9,1,6>`.
- A and B have ≤ 100,000 items; 5 s limit. Each test checks only one function. You may add includes/helpers in `student.h`.

## 2. What it really means
Both are "walk one list in order, and ask **is x in the other list?**". That question must be fast.

```text
A = 4 6 9 0 7      B = 0 3 2 4 5
Union:     4 6 9 0 7 | 3 2 5      (B's items that A lacks, in B's order)
Intersect of <3,9,0,1,6> and <4,6,9,1,7>:  9 1 6   (A's order)
```

## 3. What, why, how
- **Naive:** for each x, scan the other vector → O(|A|·|B|) = 10¹⁰. Too slow even with 5 s.
- **Right idea:** put the other list into a `std::set<T>` (O(n log n)), then each membership test is O(log n). Total O((|A| + |B|) log n).
- **Don't sort the answer** — the order is part of the answer. The set is only a lookup table.
- Works for any T with `<` (it's a template).

## 5. Traps
- **Using `set_union` / `set_intersection`**: they need *sorted* input and produce sorted output — wrong order.
- **Returning a `set`** instead of a `vector` loses the order.
- **Intersect in B's order**: the spec says A's order (`Intersect(A,B) ≠ Intersect(B,A)` in general).
- **O(n·m) with `std::find`** passes small tests only.

## 1. โจทย์บอกอะไร
**เซตแบบมีลำดับ** คือรายการที่ไม่มีตัวซ้ำและลำดับมีความหมาย (เก็บใน `std::vector`) ให้เขียน:

- `Union(A,B)`: ทุกตัวที่อยู่ใน A หรือ B โดย **ตัวของ A มาก่อนตัวที่มีแค่ใน B** `Union(<4,6,9,0,7>, <0,3,2,4,5>) = <4,6,9,0,7,3,2,5>`
- `Intersect(A,B)`: ตัวที่อยู่ทั้งสองเซต **ตามลำดับของ A** `Intersect(<3,9,0,1,6>, <4,6,9,1,7>) = <9,1,6>`
- A และ B มีไม่เกิน 100,000 ตัว เวลา 5 วินาที แต่ละชุดทดสอบตรวจแค่ฟังก์ชันเดียว เพิ่ม include/ฟังก์ชันช่วยใน `student.h` ได้

## 2. จริง ๆ แล้วถามอะไร
ทั้งสองฟังก์ชันคือ "ไล่ลิสต์หนึ่งตามลำดับ แล้วถามว่า **x อยู่ในอีกลิสต์ไหม?**" คำถามนี้ต้องตอบเร็ว

```text
A = 4 6 9 0 7      B = 0 3 2 4 5
Union:     4 6 9 0 7 | 3 2 5      (B's items that A lacks, in B's order)
Intersect of <3,9,0,1,6> and <4,6,9,1,7>:  9 1 6   (A's order)
```

## 3. อะไร ทำไม อย่างไร
- **วิธีตรง ๆ:** แต่ละ x ไล่หาในอีก vector → O(|A|·|B|) = 10¹⁰ ช้าเกินแม้ให้ 5 วินาที
- **แนวคิดที่ถูก:** ใส่อีกลิสต์ลง `std::set<T>` (O(n log n)) แล้วเช็กสมาชิกแต่ละครั้ง O(log n) รวม O((|A| + |B|) log n)
- **อย่า sort คำตอบ** — ลำดับเป็นส่วนหนึ่งของคำตอบ set เป็นแค่ตารางสำหรับค้น
- ใช้ได้กับ T ใดก็ได้ที่มี `<` (เป็น template)

```text
vector A (เก็บลำดับ)      set inA (ค้นเร็ว)
[4][6][9][0][7]     →     {0, 4, 6, 7, 9}  ← เรียงในตัว ใช้ถาม "มีไหม?"
```

## 5. จุดที่มักพลาด
- **ใช้ `set_union` / `set_intersection`**: ต้องการข้อมูลที่ *เรียงแล้ว* และให้ผลที่เรียงแล้ว — ลำดับผิด
- **คืน `set`** แทน `vector` ทำให้ลำดับหาย
- **Intersect ตามลำดับของ B**: โจทย์บอกให้ใช้ลำดับของ A (`Intersect(A,B) ≠ Intersect(B,A)` โดยทั่วไป)
- **O(n·m) ด้วย `std::find`** ผ่านแค่ชุดเล็ก
