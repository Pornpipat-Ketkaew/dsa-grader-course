## 1. What the problem says
Add `void uniq()` to CP::vector: after the call no value appears twice. If a value appears more than once, **the copies that appear later are removed**. Example: {5,1,2,3,1,1,4,1,1,2,3,5} → {5,1,2,3,4}.

- It only has to work for **string, int, float** — all three can be compared with `<`.
- The grader's `main` differs from yours: it also tests float and string.

## 2. What it really means
Walk left to right and keep a value **only the first time** you meet it. The kept values stay in their original order.

```text
v:     5  1  2  3  1  1  4  1  1  2  3  5
keep?  ✓  ✓  ✓  ✓  ✗  ✗  ✓  ✗  ✗  ✗  ✗  ✗
result 5  1  2  3  4
```

## 3. What, why, how
- **Naive:** for each element, scan everything before it to check for a copy → O(n²). With n around 10⁵–10⁶ that is too slow.
- **Sort + `std::unique`:** fast, but **destroys the order** (the answer must be 5 1 2 3 4, not 1 2 3 4 5).
- **Right idea:** a `std::set<T> seen` answers "have I kept this value already?" in O(log n). Combine it with the **read/write compaction** from Erase Many: read index r, write index w ≤ r.
- `set` works for all three types because it only needs `<` — that is the hint in the problem.
- Cost: O(n log n) time, O(number of distinct values) extra memory.

## 5. Traps
- **Sorting** changes the order → wrong answer.
- **`unordered_set`** needs a hash; it works for these three types but `set` is the safe choice the hint points to.
- **Erasing in place with `erase`** for every repeat → O(n²) shifting.
- **Comparing floats with `==` in a nested loop** is what the set avoids; the set treats two floats as equal when neither is `<` the other.
- Forgetting `#include <set>` at the top of `student.h`.

## 1. โจทย์บอกอะไร
เพิ่ม `void uniq()` ให้ CP::vector หลังเรียกแล้วจะไม่มีค่าใดซ้ำ ถ้าค่าใดมีมากกว่า 1 ตัว **ตัวที่ปรากฏทีหลังต้องหายไป** ตัวอย่าง: {5,1,2,3,1,1,4,1,1,2,3,5} → {5,1,2,3,4}

- ต้องใช้ได้กับ **string, int, float** เท่านั้น — ทั้งสามแบบเปรียบเทียบด้วย `<` ได้
- `main` ใน grader ต่างจากที่ได้รับ: ทดสอบ float และ string ด้วย

## 2. จริง ๆ แล้วถามอะไร
ไล่จากซ้ายไปขวา เก็บค่าไว้ **เฉพาะครั้งแรก** ที่เจอ ค่าที่เก็บไว้ยังเรียงตามลำดับเดิม

```text
v:     5  1  2  3  1  1  4  1  1  2  3  5
keep?  ✓  ✓  ✓  ✓  ✗  ✗  ✓  ✗  ✗  ✗  ✗  ✗
result 5  1  2  3  4
```

เหมือนจดรายชื่อคนเข้างาน: ใครมาครั้งแรกจดชื่อ ใครเดินผ่านประตูซ้ำไม่ต้องจดอีก

## 3. อะไร ทำไม อย่างไร
- **วิธีตรง ๆ:** แต่ละตัวไล่ดูทุกตัวก่อนหน้าว่าซ้ำไหม → O(n²) ถ้า n ราว 10⁵–10⁶ ช้าเกินไป
- **sort + `std::unique`:** เร็ว แต่ **ทำลายลำดับ** (คำตอบต้องเป็น 5 1 2 3 4 ไม่ใช่ 1 2 3 4 5)
- **แนวคิดที่ถูก:** ใช้ `std::set<T> seen` ตอบว่า "ค่านี้เก็บไปแล้วหรือยัง?" ใน O(log n) ร่วมกับ **การบีบอัดแบบอ่าน/เขียน** จากข้อ Erase Many: index อ่าน r, index เขียน w ≤ r
- `set` ใช้ได้กับทั้งสามชนิดเพราะต้องการแค่ `<` — นี่คือคำใบ้ในโจทย์
- เวลา O(n log n) หน่วยความจำเพิ่ม O(จำนวนค่าที่ไม่ซ้ำ)

```text
seen = { }            r อ่านทีละตัว
r=0: 3 ไม่อยู่ใน seen → เก็บ, seen = {3}
r=1: 2 ไม่อยู่        → เก็บ, seen = {2,3}
r=3: 2 อยู่แล้ว        → ข้าม
```
