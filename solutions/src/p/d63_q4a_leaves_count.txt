## 1. What the problem says
Add `size_t leaves_count()` to `CP::map_bst`: return the number of **leaf nodes** (nodes with no children) in the BST. A helper `size_t leaves_count(node* n)` (leaves in the subtree rooted at n) is already declared for you to fill in and call.

- Edit only `student.h`; any STL is allowed; **no input/output** in `student.h`.
- `main` reads n and n keys. **Before** each insert it prints `Leaves = <count>`, and once more after the last insert. The grader's `main` is different but tests the same way.

## 2. What it really means
A leaf is a node whose `left` and `right` are both `NULL`. Sample 2 inserts 3 1 2 4 5:

```text
before 3:  (empty)            Leaves = 0
before 1:  3                  Leaves = 1   (3 alone is a leaf)
before 2:  3                  Leaves = 1   (1 is the leaf, 3 is not any more)
          /
         1
before 4:  3                  Leaves = 1   (only 2)
          /
         1
          \
           2
before 5:  3                  Leaves = 2   (2 and 4)
          / \
         1   4
          \
           2
at end:    3                  Leaves = 2   (2 and 5; 4 stopped being a leaf)
          / \
         1   4
          \   \
           2   5
```

## 3. What, why, how
- "How many leaves below n?" splits naturally into "how many on the left + how many on the right". That is recursion.
- Three cases for `leaves_count(n)`:
  1. `n == NULL` → an empty subtree has **0** leaves (the base case that stops the recursion).
  2. `n` has no children → `n` itself is a leaf → **1**.
  3. otherwise → `leaves_count(n->left) + leaves_count(n->right)`. `n` is not a leaf, so it adds nothing itself.
- `leaves_count()` just returns `leaves_count(mRoot)`.
- **Cost:** every node is visited once → O(n). Depth of recursion = height of the tree.

## 5. Traps
- **Forgetting the NULL case:** a node with one child calls the helper on its NULL side. Without `if (n == NULL) return 0;` you dereference NULL.
- **Counting nodes instead of leaves:** `1 + left + right` is the size. A leaf is only counted when **both** children are NULL.
- **Counting a node with one child as a leaf** (`left == NULL || right == NULL`): node 1 above would be counted wrongly.
- **Empty tree:** must give 0. `leaves_count(mRoot)` with mRoot = NULL handles it via case 1.
- **Printing inside student.h:** forbidden; `main` does the printing.

## 3. อะไร ทำไม อย่างไร
- คำถาม "ใต้ n มีใบกี่ใบ?" แตกได้เป็น "ฝั่งซ้ายมีกี่ใบ + ฝั่งขวามีกี่ใบ" นี่คือการเวียนเกิด
- `leaves_count(n)` มีสามกรณี:
  1. `n == NULL` → ต้นไม้ย่อยว่างมีใบ **0** ใบ (กรณีฐานที่ทำให้การเวียนเกิดหยุด)
  2. `n` ไม่มีลูกเลย → `n` เป็นใบเอง → **1**
  3. นอกนั้น → `leaves_count(n->left) + leaves_count(n->right)` ตัว `n` ไม่ใช่ใบ จึงไม่นับตัวเอง
- `leaves_count()` แค่คืน `leaves_count(mRoot)`
- **เวลา:** เยี่ยมทุกโหนดครั้งเดียว → O(n) ความลึกของการเวียนเกิด = ความสูงของต้นไม้

## 5. จุดที่มักพลาด
- **ลืมกรณี NULL:** โหนดที่มีลูกตัวเดียวจะเรียกฟังก์ชันกับฝั่งที่เป็น NULL ถ้าไม่มี `if (n == NULL) return 0;` จะอ่านพอยน์เตอร์ NULL แล้วพัง
- **นับโหนดแทนนับใบ:** `1 + left + right` คือขนาดต้นไม้ ใบจะนับก็ต่อเมื่อลูก **ทั้งสองข้าง** เป็น NULL
- **นับโหนดที่มีลูกตัวเดียวเป็นใบ** (`left == NULL || right == NULL`): โหนด 1 ข้างบนจะถูกนับผิด
- **ต้นไม้ว่าง:** ต้องได้ 0 ซึ่ง `leaves_count(mRoot)` ที่ mRoot = NULL จัดการให้แล้วผ่านกรณีที่ 1
- **พิมพ์ใน student.h:** ห้าม `main` เป็นคนพิมพ์
