## 1. What the problem says
CP::priority_queue (a binary heap) has no way to delete an arbitrary value. Write `void erase(T v)`: find v and remove it so the array **is still a valid binary heap**. All values are distinct.

- The file contains the whole class and `main`; fill in `erase` only.
- Commands: `i v` push, `x` pop the max, `d v` erase v, `q` quit → `check_and_print` verifies the heap and prints by popping.
- Example from the text: insert 5 3 7 1 2, erase 3, insert 13, pop twice (13, 7), erase 2 → prints `5 1`.

## 2. What it really means
Removing from the **end** of the array keeps the tree complete. So: put the last element into the hole, shrink by one, and repair just that one position.

```text
max-heap:       15                erase 10:        15                after fixDown:   15
              /    \              last = 3 → hole  /    \                           /    \
            10      5                             3      5                         3      5
           /  \    /                             / \                              / \
          1    2  3                             1   2                            1   2
array: 15 10 5 1 2 3            array: 15 3 5 1 2       (3 ≥ 1, 3 ≥ 2: already fine)
```

## 3. What, why, how
1. **Find** v: a heap isn't sorted, so scan all slots (O(n)). Test equality with the comparator: `!mLess(a,v) && !mLess(v,a)`.
2. If not found → do nothing.
3. `mData[idx] = mData[mSize−1]; mSize−−`.
4. The moved element came from a different branch — it may be **bigger than its new parent** (go up) or **smaller than a child** (go down). Call **both** `fixUp(idx)` and `fixDown(idx)`; the one that isn't needed does nothing.

## 5. Traps
- **Shifting everything left after idx** (like a vector erase) changes parent/child relations of many nodes → the result is usually **not a heap**.
- **Only `fixDown`**: when the moved element is larger than its new parent (it came from another subtree), it must go **up**. Example: heap 100 / 50 90 / 10 20 80 85 — erase 10 → 85 moves to slot 3, its parent 50 < 85 → needs fixUp.
- **Not handling "v not found"**: without the check, `idx` stays at a default value and you delete the wrong element.
- **Erasing the last element itself**: after `mSize−−` there is nothing to fix — return early (fixUp/fixDown on idx = mSize would read past the end).

## 6. Background
Lesson 06: heap operations = "break one spot, then repair along one path": push = add at end + fixUp, pop = move last to root + fixDown, **erase = move last to the hole + fixUp + fixDown**. With an index map (value → slot) the search becomes O(1) and erase is O(log n) — that's how Dijkstra's decrease-key heaps work.

## 1. โจทย์บอกอะไร
CP::priority_queue (binary heap) ไม่มีฟังก์ชันลบค่าใด ๆ ออก ให้เขียน `void erase(T v)`: หา v แล้วลบออก โดยอาร์เรย์ **ยังเป็นฮีปที่ถูกต้อง** ค่าทุกตัวไม่ซ้ำกัน

- ไฟล์มีทั้งคลาสและ `main` แล้ว เติมแค่ `erase`
- คำสั่ง: `i v` push, `x` pop ค่ามากสุด, `d v` ลบ v, `q` จบ → `check_and_print` ตรวจฮีปแล้วพิมพ์ด้วยการ pop
- ตัวอย่างในเนื้อโจทย์: ใส่ 5 3 7 1 2, ลบ 3, ใส่ 13, pop สองครั้ง (13, 7), ลบ 2 → พิมพ์ `5 1`

## 2. จริง ๆ แล้วถามอะไร
การลบจาก **ท้าย** อาร์เรย์ทำให้ต้นไม้ยังสมบูรณ์ ดังนั้น: เอาตัวสุดท้ายมาใส่ช่องที่ว่าง ลดขนาดหนึ่ง แล้วซ่อมแค่ตำแหน่งนั้น

```text
max-heap:       15                erase 10:        15                after fixDown:   15
              /    \              last = 3 → hole  /    \                           /    \
            10      5                             3      5                         3      5
           /  \    /                             / \                              / \
          1    2  3                             1   2                            1   2
array: 15 10 5 1 2 3            array: 15 3 5 1 2       (3 ≥ 1, 3 ≥ 2: already fine)
```

เหมือนพนักงานลาออกกลางองค์กร: ดึงคนจากตำแหน่งท้ายสุดมาแทน แล้วค่อยเลื่อนขั้นขึ้นหรือลดขั้นลงจนเข้าที่

## 3. อะไร ทำไม อย่างไร
1. **หา** v: ฮีปไม่ได้เรียง ต้องไล่ทุกช่อง (O(n)) เช็กเท่ากันด้วย comparator: `!mLess(a,v) && !mLess(v,a)`
2. ถ้าไม่เจอ → ไม่ทำอะไร
3. `mData[idx] = mData[mSize−1]; mSize−−`
4. ตัวที่ย้ายมาเคยอยู่คนละกิ่ง — อาจ **ใหญ่กว่าพ่อใหม่** (ต้องขึ้น) หรือ **เล็กกว่าลูก** (ต้องลง) ให้เรียก **ทั้ง** `fixUp(idx)` และ `fixDown(idx)` ตัวที่ไม่จำเป็นจะไม่ทำอะไร

## 5. จุดที่มักพลาด
- **เลื่อนทุกตัวหลัง idx ไปซ้าย** (แบบ erase ของ vector) ทำให้ความสัมพันธ์พ่อ-ลูกของหลายโหนดเปลี่ยน → ผลมักจะ **ไม่เป็นฮีป**
- **เรียกแค่ `fixDown`**: ถ้าตัวที่ย้ายมาใหญ่กว่าพ่อใหม่ (มาจากอีกกิ่ง) ต้อง **ขึ้น** ตัวอย่าง: ฮีป 100 / 50 90 / 10 20 80 85 — ลบ 10 → 85 ย้ายมาช่อง 3 พ่อคือ 50 < 85 → ต้อง fixUp
- **ไม่จัดการกรณี "ไม่เจอ v"**: ถ้าไม่เช็ก `idx` จะเป็นค่าเริ่มต้นและไปลบผิดตัว
- **ลบตัวสุดท้ายเอง**: หลัง `mSize−−` ไม่มีอะไรต้องซ่อม — return เลย (fixUp/fixDown ที่ idx = mSize จะอ่านเลยท้าย)

## 6. ความรู้พื้นฐาน
บทที่ 06: การทำงานของฮีป = "ทำให้เสียหนึ่งจุด แล้วซ่อมตามเส้นทางเดียว": push = ใส่ท้าย + fixUp, pop = ย้ายตัวสุดท้ายไปราก + fixDown, **erase = ย้ายตัวสุดท้ายไปช่องว่าง + fixUp + fixDown** ถ้ามีตาราง (ค่า → ช่อง) การค้นหาจะเป็น O(1) และ erase เป็น O(log n) — แบบที่ heap ของ Dijkstra ใช้ทำ decrease-key
