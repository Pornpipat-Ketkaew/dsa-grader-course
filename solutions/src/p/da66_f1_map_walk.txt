## 1. What the problem says
A map has R rows and C columns (1 ≤ R, C ≤ 10); cell (r, c) is row r from the top, column c from the left. A character starts at **(1,1)** and wants to reach **(R,C)**. Commands:
- **A** = move right to (r, c+1); **B** = move down to (r+1, c); **C** = move up to (r−1, c).

Rules: never leave the map; **never enter a cell visited before**; never enter a **no-entry** cell (marked 1 in the input); the game **ends immediately** when (R,C) is reached.

Print **every** different command string that reaches (R,C), one per line, **in alphabetical order**, then a line `DONE`. Memory limit **32 MB**. Subtasks: 10% R, C ≤ 2 without walls; 10% R, C ≤ 3 without walls; 15% R, C ≤ 3; 25% no answer contains C; 40% nothing else.

## 2. What it really means
Enumerate all **simple paths** from the top-left to the bottom-right using only right / down / up steps. Sample 2 (2 × 3, no walls):

```text
  (1,1) (1,2) (1,3)          AAB    → → ↓
  (2,1) (2,2) (2,3)          ABA    → ↓ →
                             BAA    ↓ → →
                             BACAB  ↓ → ↑ → ↓
```

Since there is no "left" move, the path crosses each column once: in each column it goes up or down for a while, then steps right.

## 3. What, why, how
- **DFS with backtracking:** `walk(r, c, len)` stands on (r,c) with `len` commands so far. If (r,c) is the goal, output the path and **return** (the game ends). Otherwise try the 3 moves; for each legal one, mark the new cell visited, write the letter, recurse, then **unmark** (so other paths may use the cell).
- **Alphabetical order for free:** try moves in the order **A, B, C**. Two different answers first differ at some step, and at that step DFS explored the smaller letter first. No answer is a prefix of another (the game stops at the goal), so this is exactly alphabetical order.
- **Why `visited` must be undone:** a cell used by one path may be needed by another path later (BAA and BACAB both use (2,2)).
- **Memory 32 MB:** the number of answers can be huge (on an empty R×R map it is R^(R−1): every column except the last can be left from any row). Never store all answers; print each one when found. A small buffer keeps it fast.
- **Cost:** proportional to the number of explored partial paths; the tests keep the output printable.

## 5. Traps
- **Continuing after reaching the goal:** the rule says the game ends. Without the early `return`, a path that reaches (R,C) from the left could go on upward (C) and then never get back, which wastes time, or, with other move sets, produce extra answers. Stop at the goal.
- **Forgetting to unmark `visited`:** later paths miss cells and answers disappear.
- **Collecting all answers in a vector and sorting:** memory explodes on big outputs (32 MB) and it's unnecessary because DFS order is already alphabetical.
- **Forgetting `DONE`**, also when there is no path (sample 3).
- **1 × 1 map:** start = goal, so there is one answer, the empty command string, printed as an empty line before `DONE`.

## 6. Background
Lesson 11: **backtracking on a grid** (mark, recurse, unmark) and **output in a required order by ordering the choices**. With only right/down moves (the 25% subtask), the count could be found with DP; with the up move and no revisits, enumeration by DFS is the natural tool. For "shortest path" instead of "all paths", BFS is the right tool (Lesson 16, see Dungeon).

## 1. โจทย์บอกอะไร
แผนที่มี R แถว C คอลัมน์ (1 ≤ R, C ≤ 10) ช่อง (r, c) คือแถวที่ r นับจากบน คอลัมน์ที่ c นับจากซ้าย ตัวละครเริ่มที่ **(1,1)** และต้องการไป **(R,C)** คำสั่ง:
- **A** = เดินไปขวา (r, c+1); **B** = เดินลง (r+1, c); **C** = เดินขึ้น (r−1, c)

กฎ: ห้ามเดินออกนอกแผนที่; **ห้ามเข้าช่องที่เคยไปแล้ว**; ห้ามเข้า **ช่องห้ามเข้า** (ค่า 1 ในข้อมูลนำเข้า); เมื่อถึง (R,C) **เกมจบทันที**

พิมพ์ลำดับคำสั่ง **ทุกแบบ** ที่ไปถึง (R,C) บรรทัดละแบบ **เรียงตามตัวอักษร** แล้วปิดท้ายด้วยบรรทัด `DONE` หน่วยความจำจำกัด **32 MB** ชุดทดสอบ: 10% R, C ≤ 2 ไม่มีช่องห้ามเข้า; 10% R, C ≤ 3 ไม่มีช่องห้ามเข้า; 15% R, C ≤ 3; 25% ไม่มีคำตอบที่มีคำสั่ง C; 40% ไม่มีเงื่อนไขอื่น

## 2. จริง ๆ แล้วถามอะไร
แจกแจง **เส้นทางที่ไม่ซ้ำช่อง** ทั้งหมดจากมุมซ้ายบนไปมุมขวาล่าง โดยใช้แค่ ขวา / ลง / ขึ้น ตัวอย่างที่ 2 (2 × 3 ไม่มีช่องห้ามเข้า):

```text
  (1,1) (1,2) (1,3)          AAB    → → ↓
  (2,1) (2,2) (2,3)          ABA    → ↓ →
                             BAA    ↓ → →
                             BACAB  ↓ → ↑ → ↓
```

เพราะไม่มีคำสั่ง "ซ้าย" เส้นทางจึงผ่านแต่ละคอลัมน์ครั้งเดียว: ในแต่ละคอลัมน์จะขึ้นหรือลงไปช่วงหนึ่ง แล้วก้าวไปทางขวา (เหมือนเดินในเขาวงกตที่ประตูหมุนให้เดินไปทางขวาได้อย่างเดียว)

## 3. อะไร ทำไม อย่างไร
- **DFS แบบ backtracking:** `walk(r, c, len)` ยืนอยู่ที่ (r,c) มีคำสั่งแล้ว `len` ตัว ถ้า (r,c) คือเป้าหมาย พิมพ์เส้นทางแล้ว **return** (เกมจบ) ไม่งั้นลอง 3 ทาง ทางที่ถูกกฎ: ทำเครื่องหมายช่องใหม่ว่าไปแล้ว เขียนตัวอักษร เรียกเวียนเกิด แล้ว **ลบเครื่องหมายออก** (ให้เส้นทางอื่นใช้ช่องนั้นได้)
- **เรียงตามตัวอักษรได้ฟรี:** ลองตามลำดับ **A, B, C** คำตอบสองแบบที่ต่างกันจะต่างกันครั้งแรกที่ขั้นหนึ่ง และที่ขั้นนั้น DFS สำรวจตัวอักษรที่น้อยกว่าก่อน ไม่มีคำตอบไหนเป็นส่วนต้นของอีกคำตอบ (เกมหยุดที่เป้าหมาย) จึงได้ลำดับตัวอักษรพอดี
- **ทำไมต้องลบเครื่องหมาย `visited`:** ช่องที่เส้นทางหนึ่งใช้ อาจจำเป็นสำหรับเส้นทางอื่นในภายหลัง (BAA และ BACAB ใช้ (2,2) ทั้งคู่)
- **หน่วยความจำ 32 MB:** จำนวนคำตอบอาจมหาศาล (บนแผนที่ว่าง R×R มี R^(R−1) แบบ: ทุกคอลัมน์ยกเว้นคอลัมน์สุดท้ายออกได้จากทุกแถว) ห้ามเก็บคำตอบทั้งหมด ให้พิมพ์ทันทีที่เจอ บัฟเฟอร์เล็ก ๆ ช่วยให้เร็ว
- **เวลา:** แปรผันตามจำนวนเส้นทางบางส่วนที่สำรวจ ชุดทดสอบออกแบบให้ผลลัพธ์พิมพ์ได้ทัน

## 5. จุดที่มักพลาด
- **เดินต่อหลังถึงเป้าหมาย:** กฎบอกว่าเกมจบ ถ้าไม่ `return` ทันที เส้นทางอาจผ่านเป้าหมายแล้วไปต่อ ทำให้ได้คำตอบเกิน
- **ลืมลบเครื่องหมาย `visited`:** เส้นทางต่อ ๆ ไปจะใช้ช่องไม่ได้ คำตอบหาย
- **เก็บคำตอบทั้งหมดใน vector แล้ว sort:** หน่วยความจำระเบิดเมื่อผลลัพธ์เยอะ (32 MB) และไม่จำเป็นเพราะลำดับของ DFS เรียงตามตัวอักษรอยู่แล้ว
- **ลืม `DONE`** รวมถึงตอนที่ไม่มีเส้นทางเลย (ตัวอย่างที่ 3)
- **แผนที่ 1 × 1:** จุดเริ่ม = เป้าหมาย มีคำตอบเดียวคือลำดับคำสั่งว่าง พิมพ์เป็นบรรทัดว่างก่อน `DONE`

## 6. ความรู้พื้นฐาน
บทที่ 11: **backtracking บนตาราง** (ทำเครื่องหมาย เวียนเกิด ลบเครื่องหมาย) และ **ได้ผลลัพธ์ตามลำดับที่ต้องการโดยเรียงทางเลือกให้ถูก** ถ้ามีแค่ขวา/ลง (ชุดทดสอบ 25%) การนับจำนวนใช้ DP ได้ แต่เมื่อมีการเดินขึ้นและห้ามซ้ำช่อง การแจกแจงด้วย DFS คือเครื่องมือที่เหมาะ ถ้าถาม "เส้นทางสั้นที่สุด" แทน "ทุกเส้นทาง" ให้ใช้ BFS (บทที่ 16 ดูข้อ Dungeon)
