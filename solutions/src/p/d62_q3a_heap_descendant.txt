==== en
## 1. What the problem says
A binary heap stored in an array with the root at index 0. Node a is an **ancestor** of b if a is b's parent, or the parent of b's parent, and so on; then b is a **descendant** of a. Given n and a (0 ≤ a < n ≤ 200,000), print the count m of a and all its descendants, then their indices in increasing order.

## 2. What it really means
Children of i are 2i+1 and 2i+2. Going down one level from a contiguous range of nodes gives another contiguous range:

```text
n = 7, a = 2                     index layout
level 0: [2, 2]                        0
level 1: [5, 6]                     1     2
level 2: [11, 14] → beyond n=7     3 4   5 6
answer: 3 / 2 5 6
```

## 3. What, why, how
- Start with `lo = hi = a`. While `lo < n`: output `lo .. min(hi, n−1)`, then `lo = 2·lo + 1`, `hi = 2·hi + 2`.
- Each new range starts after the previous one ends, so the output is already sorted.
- O(m) — only the answer is touched. (A brute force that checks every b by walking up is O(n log n), also fine for n = 2·10⁵, but this is cleaner.)
- Use `long long` for lo/hi: hi doubles every level and can overshoot int before the loop stops.

## 5. Traps
- **Forgetting a itself** — the count includes a.
- **Recursion with printing** visits nodes depth-first: 214, 429, 859, … — not sorted.
- **Cutting the last level** at n−1 (sample `6 2` → only 5, not 6).

## 6. Background
Lesson 06: array heap arithmetic — parent (i−1)/2, children 2i+1 and 2i+2. The descendants at depth d below a form the range [2ᵈ(a+1)−1, 2ᵈ(a+2)−2]. The same level-range idea solves Heap Before Node.

## 1. โจทย์บอกอะไร
ฮีปแบบไบนารีเก็บในอาร์เรย์โดยรากอยู่ index 0 โหนด a เป็น **บรรพบุรุษ** ของ b ถ้า a เป็นพ่อของ b หรือพ่อของพ่อของ b ไปเรื่อย ๆ แล้ว b เรียกว่า **ลูกหลาน** (descendant) ของ a ให้ n และ a (0 ≤ a < n ≤ 200,000) พิมพ์จำนวน m ของ a รวมลูกหลานทั้งหมด แล้วพิมพ์ index เรียงจากน้อยไปมาก

## 2. จริง ๆ แล้วถามอะไร
ลูกของ i คือ 2i+1 และ 2i+2 ถ้าลงไปหนึ่งชั้นจากช่วงโหนดที่ติดกัน ก็จะได้อีกช่วงที่ติดกัน:

```text
n = 7, a = 2                     index layout
level 0: [2, 2]                        0
level 1: [5, 6]                     1     2
level 2: [11, 14] → beyond n=7     3 4   5 6
answer: 3 / 2 5 6
```

เหมือนผังตระกูล: ลูกหลานรุ่นเดียวกันของ a นั่งติดกันเป็นแถวในอาร์เรย์เสมอ

## 3. อะไร ทำไม อย่างไร
- เริ่ม `lo = hi = a` ขณะที่ `lo < n`: พิมพ์ `lo .. min(hi, n−1)` แล้ว `lo = 2·lo + 1`, `hi = 2·hi + 2`
- ช่วงใหม่เริ่มหลังช่วงเก่าจบเสมอ ผลลัพธ์จึงเรียงอยู่แล้ว
- O(m) — แตะเฉพาะคำตอบ (brute force ที่เช็กทุก b โดยเดินขึ้นไปเป็น O(n log n) ก็ผ่านสำหรับ n = 2·10⁵ แต่วิธีนี้สะอาดกว่า)
- ใช้ `long long` กับ lo/hi เพราะ hi เพิ่มเท่าตัวทุกชั้น อาจเกิน int ก่อนลูปหยุด
